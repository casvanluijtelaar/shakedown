# Open questions

## Questions for the owner

None open. A question the specification cannot settle is added here with its options, a recommendation and its reason, and its row is removed once the owner's answer is written into the spec where it applies.

## Spikes

Measurements the specification depends on. Each has a pass condition and what the spec says if it fails. A spike runs on the Windows test machine in the milestone that first needs it; its result goes into `research/` and the spec is edited in place to the answer.

| # | Question | Pass condition | If it fails |
|---|---|---|---|
| **SPK-01** | Round trip through the extension and its callback on each kind of machine (research RX-1, RX-2, RX-4, RX-7). | The runner sends `1 + 1` to a singleplayer `p1`, a dedicated `server`, a client and a headless client; each returns `2`, 100 round trips per machine, none lost, none run twice across a mission restart, no 301 warning in any RPT; the 95th percentile is under 1 s. | A machine kind whose callback does not fire receives orders through `remoteExec` from the server's agent, with correlation ids, and answers through its own extension; `P-03` is edited to say so. |
| **SPK-02** | Large orders and results (RX-3). | A 1 MB check source reaches the lead through `fetch` in parts and a 1 MB result reaches the runner through `send`, intact, with no frame over 100 ms. | The part size of `INT-AR-03` is lowered until the frame limit holds. |
| **SPK-03** | The session token through the environment (RX-5). | The extension in each kind of game process started by the runner reads `SHAKEDOWN_TOKEN` and the three other variables. | The runner writes a file per machine, readable by the current user only, into the machine's profile folder, and passes nothing else; `SEC-02` is edited. |
| **SPK-04** | Reset in place (research `14-sessions.md`). | 20 checks in one singleplayer session and 20 in one dedicated session (2 clients, 1 headless client), each creating units, vehicles and objects and changing time, weather and the player; after each reset every machine shows the baseline and the reset takes under 2 s. | Whatever the reset cannot restore is listed in the check API contract as needing `@reset mission`, and `NFR-PF-04` is set from the measurement. |
| **SPK-05** | A singleplayer session survives the player's death, and `endMission` moves `-autotest` to the next copy of the session mission. | With `respawn = 3` in the session mission, `p1` dies 10 times in one `-autotest` session; the mission keeps running each time and the reset brings `p1` back; then `endMission "END1"` loads the next list entry in under 3 s, 10 of 10. | First fallback: a `Killed` handler in the agent hands `p1` to a new unit of the same class at the baseline with `selectPlayer` before the engine ends the mission. Second: the session starts with `-init=playMission[...]` instead of `-autotest`, and a level-B reload in singleplayer becomes a game restart. |
| **SPK-06** | The runner outlives the client that started it, and dies with its game (research `17-health.md`, `19-agent-tools.md`). | Under Claude Code on the test machine, an MCP call starts a dedicated session; the Claude Code session ends; a new one finds the session `ready`. Then the runner is killed with `taskkill /F`, and no `arma3_x64` or `arma3server_x64` process of the session is left within 10 s, 5 of 5. | If breakaway is refused and WMI also fails, the runner is started as a per-user scheduled task; `INT-WIN-02` is edited. |
| **SPK-07** | `ScriptError` on every machine and every kind of code (research `16-observation.md`). | A deliberate error in unscheduled code, spawned code and a `remoteExec`'d function raises it on the machine where it ran, with file and line, on all four machine kinds; every error the RPT shows from mission start on was caught by the handler or the RPT scan. | The RPT scan becomes the primary source for the machine kinds where the handler is silent, and errors there are attributed by time only. |
| **SPK-08** | The time of a `mission-restart` reload, and CBA's cache off through the session mission (research HR-4, HR-5). | On a dedicated session with 2 clients and a CBA mod, an edited `PREP` function is live on every machine after a level-B reload; the RPT shows CBA's cache disabled; the time from the reload order to every machine ready is recorded over 10 reloads. | If the cache stays on, the session loads CBA's `cba_cache_disable.pbo` from the CBA folder; `INT-CBA-02` is edited. The measured time sets `NFR-PF-02`'s target. |
| **SPK-09** | `BIS_fnc_recompile` on an addon's `CfgFunctions` function mid-mission (research HR-1). | With `allowFunctionsRecompile = 1` and an edited file in the dev build, recompiling `TAG_fnc_x` on the server and a client makes both return the new value without a mission restart. | Every `.sqf` change is level `mission-restart`; `RLD-02` loses its level-A row for mod code. |
| **SPK-10** | Does `action ["User", ...]` honour an action's condition and radius? | Out of radius the action's script does not run; in radius with the condition true it runs once. | `ACT-01` already checks condition and radius itself before firing, so the check stays; if the engine honours them, the framework's check stays as the source of the failure message. |
| **SPK-11** | Key input to one background game window (research `15-player-input.md`). | With `-noPause`, the game not in the foreground and another window focused, posted `WM_KEYDOWN`/`WM_KEYUP` fire a display-46 `KeyDown` handler and a CBA keybind once; the focused window and the foreground are unchanged, with the Shadow stream connected and disconnected. | `ACT-05` is dropped. |
| **SPK-12** | Objects across machines by net id in singleplayer. | In singleplayer `objectFromNetId (netId _obj)` returns `_obj` for a created object and for `player`. | In singleplayer the agent keeps its own table from a counter to the object, and `DM-13` carries that id. |
| **SPK-13** | Reading a running game's RPT (research `16-observation.md`). | A reader sees a `diag_log` line within 2 s of the call, 100 times in a row, and the game logs no file error. | `logs` and the RPT scan read a machine's RPT only after the check ends or the session stops, and `INS-01`'s errors come from the handler alone. |
| **SPK-14** | The default ceilings (research `18-test-tools.md`; Q3). | The 10 s wait ceiling covers the slowest common wait (an action's effect replicated to every client of a dedicated session) in 95 of 100 runs, and no passing run of 50 checks comes within 5 s of a runner ceiling. | The defaults of `NFR-PF-06` are set from the measurement. |
| **SPK-15** | The thresholds of the clock watch (`HLT-02`) and the Shadow stream cut (research `17-health.md`). | Over 50 passing checks, record each machine's mission-time to real-time ratio and heartbeat gap; set thresholds none crosses; a stream cut, a suspended client and a killed client are each flagged within 15 s, 5 of 5. | The clock watch reports but does not change outcomes until thresholds hold. |
| **SPK-16** | A crash on demand (`FIX-01`) on each kind of game process. | The fixture's crash in singleplayer `p1`, a dedicated `server`, a client and a headless client ends that process within 10 s with a nonzero exit code, with no dialog holding it open, and leaves a `.mdmp` or `.bidmp` in its profile folder, 5 of 5 per kind. | The fixture's crash ends the process with `ExitProcess` and the exit code of an access violation, and the dumps of `US-016` and `US-043` are tested with a dump the harness writes of the live process into its profile folder (`MiniDumpWriteDump`) before ending it by its process id. |
| **SPK-17** | Mission time held while frames go on (`FIX-02`, `HLT-02`). | In singleplayer, during a hold of 8 s, `time` on `p1` advances less than 0.1 s, `diag_frameNo` keeps advancing, the `EachFrame` heartbeat keeps arriving every second, and an `exec` of `1 + 1` sent during the hold answers within its ceiling plus the grace; after the hold `time` advances at the real-time rate, 10 of 10. The candidates are the engine's own pause, which stops `time` (research `17-health.md`), and `setAccTime`. | `US-059` is accepted by the owner cutting the Shadow stream during a check, as `SPK-15` does; the clock-watch rule is proven by the runner's own tests without the game; `FIX-02` is dropped. |
