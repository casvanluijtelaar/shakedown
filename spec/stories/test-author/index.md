# Test author stories

* [US-001 Start a singleplayer session once and run many checks against it](US-001-singleplayer-session.md) - A test author starts one singleplayer session and runs many checks and runs against it without the game restarting.
* [US-002 Start a dedicated server with clients and headless clients in one command](US-002-dedicated-session.md) - A test author starts a dedicated server with a chosen number of game clients and headless clients with one command and addresses each machine by its name.
* [US-003 A start is refused before any process starts when Steam, the game or a mod is missing](US-003-start-refused-missing-environment.md) - A session start whose environment is incomplete is refused before any game process starts, naming exactly what is missing.
* [US-004 A start that never becomes ready ends failed and leaves nothing running](US-004-start-never-ready.md) - A session start in which a machine exits or does not become ready within the start ceiling ends failed, names the machine and its last log lines, and stops every process it started.
* [US-005 A second session start while one runs is refused](US-005-second-session-refused.md) - Starting a session while another one runs is refused, naming the running session and how to stop it, and leaves the running session untouched.
* [US-006 A malformed project file or an unknown setup is refused with the key at fault](US-006-bad-project-file.md) - A `shakedown.toml` with an unknown key, a missing required key or a wrong type, or a start that names a setup the file does not have, is refused before anything starts, naming the key and its line.
* [US-007 The session outlives the command or the AI agent session that started it](US-007-session-outlives-client.md) - A session started from the command line or from an AI agent's MCP server keeps running when that client ends, and the next client finds it.
* [US-008 Every check starts from the session's start state](US-008-check-starts-from-baseline.md) - Before every check the framework resets the session, so a check sees the session's start state on every machine whatever the previous check created or changed.
* [US-009 The previous check killed the player](US-009-previous-check-killed-player.md) - A check that ends with a player dead is followed by a check in which that player is alive at the start position, in singleplayer and on a dedicated session.
* [US-010 A reset that cannot complete makes the next check invalid](US-010-reset-cannot-complete.md) - When the reset before a check does not complete within its ceiling, that check is invalid with what did not match, and the session is broken instead of running checks on a dirty state.
* [US-011 A check that changes what a reset cannot name gets a mission restart](US-011-mission-reset.md) - A check whose header says `@reset mission` starts in a freshly restarted session mission, for state such as global variables and mod settings that a reset in place cannot restore.
* [US-012 A mission restart before a check does not bring every machine back](US-012-mission-reset-fails.md) - When the mission restart a check asked for does not bring every machine back, the check is invalid naming the machine, and the session is broken.
* [US-013 Run code on a chosen machine and get the result back as data](US-013-run-code-on-machine.md) - A test author runs SQF on the server, a named player's machine, a headless client or a group of machines and gets the returned value back as data.
* [US-014 Code for a machine the session does not have, or code that does not compile](US-014-bad-machine-or-code.md) - Code sent to a machine the session does not have, or that does not compile there, ends a check as the author's mistake, naming the machine or the engine's message, and is refused by the command line and the tools.
* [US-015 A machine stops answering during a check](US-015-machine-stops-answering.md) - When a machine stops answering in the middle of a check, the check is invalid naming the machine, not failed, and the following checks are invalid because the session is broken.
* [US-016 A game process crashes during a check](US-016-game-crashes-during-check.md) - When a game process exits during a check, the check is invalid naming the machine, its exit code and any crash dump, and the run still writes its result file.
* [US-017 Build a scene: objects, units, a player's position and facing, time and weather](US-017-build-a-scene.md) - A test author places objects, units and vehicles, moves a player to an exact spot facing an exact way and sets the date and weather, and every machine sees the same scene, from one check that runs in singleplayer and on a dedicated server.
* [US-018 An unknown class name or a wrong argument to the check API](US-018-unknown-class-or-argument.md) - A check that creates an unknown class or calls a check API function with an argument of the wrong type or out of range ends as the author's mistake, naming the function, the argument and what it expected.
* [US-019 Make a player use a mod's action and check the result on every machine](US-019-use-mod-action.md) - A test author makes the player of a named machine use an action the mod added to an object, through the mod's real path, and asserts the outcome on the server and on every client.
* [US-020 The action cannot be used](US-020-action-cannot-be-used.md) - When the action a check asks for is missing, its condition is false or the player is out of its radius, the check fails at the ceiling saying which of the three it was, with the facts.
* [US-021 Make a player press a mod's CBA keybind](US-021-press-cba-keybind.md) - A test author makes the player of a named machine press a keybind a mod registered with CBA, running the mod's own key-down and key-up code on that machine.
* [US-022 A keybind that is not registered, or a setup without CBA](US-022-keybind-missing.md) - Pressing a keybind that is not registered, or on a machine without CBA, ends the check as the author's mistake, listing the keybinds that exist; checks that press no key run without CBA.
* [US-023 Wait for an outcome on a machine with a ceiling, never a fixed sleep](US-023-wait-with-ceiling.md) - A test author waits for a condition on a named machine until it holds or a ceiling passes, and the check goes on as soon as it holds.
* [US-024 A condition that is never met](US-024-condition-never-met.md) - A wait whose condition never holds ends the check fail at its ceiling, with what was awaited, the ceiling, and the last value seen on each machine.
* [US-025 Assert that every machine agrees with the server](US-025-machines-agree.md) - A test author reads one value on several machines and asserts that each meets an expectation, or that every machine agrees with the first one named.
* [US-026 One machine disagrees with the others](US-026-machine-disagrees.md) - When one machine's value differs from the others, the check fails naming that machine and showing every machine's value.
* [US-027 A check of an error path expects a script error](US-027-expected-error.md) - A test author declares that a block of code is expected to raise a script error containing a text, and the check passes when it does, on any machine.
* [US-028 The mod throws a script error on one client only](US-028-script-error-on-one-client.md) - A script error on one machine during a check fails it, and the result names the machine, the error, its file and line, and the step that caused it.
* [US-029 An expected script error never comes](US-029-expected-error-missing.md) - A check that expects a script error that never happens fails at its end, saying which error it waited for.
* [US-030 A script error the in-game handler misses still reaches the result](US-030-error-missed-by-handler.md) - A script error that reaches a machine's log without passing the in-game error handler is still caught from the log and fails the check like any other.
* [US-031 Run one check, a list of checks, or the checks a story or finding names](US-031-select-checks.md) - A test author or mod developer runs a single check, a list of checks in a given order, or every check whose header carries a story or finding tag, and lists the selection without starting the game.
* [US-032 A selection that matches no check](US-032-selection-matches-nothing.md) - A run or a listing whose ids or tags match no check is refused, listing what exists, and starts nothing.
* [US-033 Run the full suite and walk away](US-033-full-suite-walk-away.md) - A test author runs every check in a setup with one command that starts the session, runs, and stops it, leaving one result file, the logs, and nothing running.
* [US-034 A run is stopped by hand](US-034-run-stopped-by-hand.md) - A run stopped with Ctrl+C or `run stop` ends its executing check invalid, lists the rest as not run, writes its result file, and leaves nothing of its own running.
* [US-035 The runner dies](US-035-runner-dies.md) - When the runner process is killed, every game process it started ends within seconds, and the next start finds no process, port or file left from it.
* [US-036 Stopping a session leaves nothing running](US-036-stop-session.md) - `session stop` stops every process of the session and returns only when none is left, with no port held and no mission copy left.
* [US-037 Write a check in SQF with steps, named by the story it proves](US-037-write-check-in-sqf.md) - A test author writes a check as one SQF file with a short header and named steps, using only the check API, and the result shows each step with its times.
* [US-038 A broken check is the author's to fix](US-038-broken-check.md) - A check whose header is malformed, whose body does not compile, or that calls the check API wrongly ends fail with reason check-error saying what to fix, never invalid, and the run goes on.
* [US-039 A check runs past its timeout](US-039-check-timeout.md) - A check whose body runs past its header's timeout while every machine still answers is ended and fails with reason check-timeout, naming the step it was in.
* [US-040 Edit a check and rerun it with no reload](US-040-edit-check-rerun.md) - A test author edits a check file and reruns it against the running session; the new text runs at once, with no reload and no restart.
* [US-041 Every check ends pass, fail or invalid with its reason](US-041-one-outcome-with-reason.md) - Every check execution ends with exactly one outcome, and every outcome that is not pass carries a reason kind and a message, so a test author knows whether the mod or the environment is at fault.
* [US-042 Each machine's log is kept with the run and can be filtered](US-042-logs-with-run.md) - Each machine's log is kept with the run and per check, without Steam IDs, and a test author reads a machine's lines filtered by run, check, pattern and count.
* [US-043 The logs of a machine that crashed are kept](US-043-logs-of-crashed-machine.md) - When a machine's process exits during a run, its log lines up to the exit and its crash dump are kept with the run.
* [US-044 Ask a running game what is going on](US-044-ask-running-game.md) - A person or an AI agent asks a running machine for its state, the player and the objects around it, its running scripts and its last errors, at any time, including during a check and after one failed, without stopping anything.
* [US-045 Inspecting a machine that stopped answering](US-045-inspect-stalled-machine.md) - Asking a machine that stopped answering returns, within its ceiling, that the machine is lost, instead of hanging the person or AI agent who asked.
* [US-046 See the runner, the session and the active run at any time](US-046-status-without-game.md) - `status` answers at once with the runner, the session with each machine's state and last answer time, the active run's progress and the last reload, and works where no game or runner runs.
* [US-047 A command that needs a session when none runs](US-047-no-session.md) - A command or tool that needs a running session, called when none runs, is refused with what to do next, and starts no game.
* [US-048 An AI agent uses every capability as tools, with the same results as the command line](US-048-agent-tools.md) - An AI agent drives every capability of the command line through the `shakedown` MCP server, and gets the same JSON a person gets with `--json`.
* [US-049 An AI agent's fixable mistake gets a code and the next step](US-049-agent-fixable-error.md) - When an AI agent calls a tool wrongly, the tool returns an error with a fixed code, what is wrong and what to do next, so the agent corrects itself without a person.
* [US-050 An AI agent follows a long run without a tool call timing out](US-050-long-run-through-tools.md) - A run started through MCP returns a handle at once and is followed with calls that each stay under a minute, so a long suite never hits the agent's tool timeout.
* [US-051 A cancelled tool call stops the work it started in the game](US-051-cancelled-tool-call.md) - When the AI agent's client cancels a tool call, the work it started in the game stops, so a dropped call does not leave code running in the session.
* [US-052 Only the local user controls the session, and every piece of code sent to it is recorded](US-052-local-control-audited.md) - The framework listens on loopback only, keeps its tokens out of every command line, file and output, and records every piece of code sent to a machine.
* [US-053 A process without the token cannot run code in the session](US-053-no-token-no-code.md) - A local process that connects to the runner or poses as a game process without the right token, or from a process the runner did not start, runs no code, and the refusal is logged.
