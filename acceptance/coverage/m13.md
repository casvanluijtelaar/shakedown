# M13 Every setup, repeated: coverage

The M13 run: `python acceptance/run.py --repeat 3 --check US-074 --check US-075 --check US-076 --check US-077 --check US-078 --check US-080 --check "RUN-07 run --each-setup with a session"`, selecting the 20 M13 checks, from 12:45Z to 13:14Z on 2026-11-16. The framework was the install in `target\shakedown\`, built after `1249878`, the last M13 commit on main; `shakedown version` prints `0.1.2`. Steam ran for every start, and no start was lost to `Error 20 reading file`. 60 of 60 passed, each check 3 of 3. Two trial rounds before it passed every check once.

## How the checks drive it

Each repeat, with no session running before each part, works in projects of its own in the work folder:

- `m13each`: setups `sp` (singleplayer, `@skd_fixture`), `sp-cba` (singleplayer, CBA and both fixtures) and `dedicated-2` (a dedicated server with two clients, `@skd_fixture`), in that order; checks `US-074-every` with no `@setups`, `US-074-two` naming `sp dedicated-2`, and `US-074-one` naming `sp-cba` and tagged `solo`. `run --each-setup` in text, then `run --each-setup --tag solo --json`, with the game processes listed every second. Then `run_start` with `each_setup` through `shakedown mcp`, `run_status` twice a second, and the game process of `sp-cba` ended by its id with `taskkill /F` as soon as it appeared while `runs` gave that setup as `starting-session`.
- `m13miss`: the same, with `sp-cba` also loading the mod `ghost`, whose folder does not exist; `run --each-setup --json`.
- `m13rep`: setups `sp` and `ded` (a dedicated server with two clients), each `@skd_fixture` alone. One `sp` session for `US-076` and `US-078`; one `ded` session in which `p2` is ended by its id during the third of five repeats of `US-077-wait`, which waits 8 s on `p2` for its own clock; and `run --setup ded US-077-wait --repeat 3` with no session, `p2` ended during the first repeat. The repeats done and the step running were read with `status --json` and `inspect --machine server`.
- `m13bad`: `list`, `run` and `run --setup sp` with `slow_step = -1` and with `slow_step = "10"`.

## The stories

- **`US-074`**: `run --each-setup` exited 0 in 109 to 113 s. The game processes came in three groups, one `arma3_x64` for `sp`, one for `sp-cba`, then a server and two clients for `dedicated-2`, each gone before the next appeared, and the three runs started in the project file's order. `sp` ran `US-074-every` and `US-074-two`, `sp-cba` `US-074-every` and `US-074-one`, `dedicated-2` `US-074-every` and `US-074-two`, all `pass`, none listed as not run; `US-074-every` read `isMultiplayer` true only on `dedicated-2` and CBA on `p1` only on `sp-cba`. The output held six execution lines and three setup lines naming the three new run folders, each with a valid `result.json`. After it, and after the `solo` run, no game process ran and `status` showed no session. `--tag solo` started one `arma3_x64` process, made one run folder, and its `--json` gave one `runs` entry, `sp-cba`, and one outcome with its `setup`. `run_start` with `each_setup` answered in 0.01 s with `e-<time>-<n>`, `setups` `["sp", "sp-cba", "dedicated-2"]` and `total` 6; `run_status` named the setup that `runs` gave as starting or running, and `null` once the whole had ended. With a session running, `run --each-setup` exited 4 naming `session stop`. 3 of 3.
- **`US-075`**: with the missing folder the command exited 2 in about 78 s. The result file of `sp-cba` was valid, with `session.id` `null`, no machines, no executions, and `US-074-every` and `US-074-one` in `not_run` with reason `session-failed` and the message "the session start was refused: The session cannot start; missing: the folder ...\no-such-mod\@ghost of mod ghost. Provide what is missing and start the session again."; `run_result` gave the same folder in `session_reason`. `sp` and `dedicated-2` ran their checks to `pass`, no game process of `sp-cba` was seen, and nothing ran after. With `p1` of `sp-cba` ended during its start, `runs` ended `finished`, `session-failed`, `finished`; that setup's valid result file named its session and listed its two checks `not-run` / `session-failed` with "session s-... failed to start (p1): p1 exited with code 1 before it was ready; it was launched", and the summary of the whole was 4 `pass` and 2 not run. No game process was left. 3 of 3.
- **`US-076`**: `US-076-steady --repeat 10` exited 0 with ten executions, repeat 1 to 10, one after the other, `run.repeat` 10 and `repeats` `pass` with counts 10, 0, 0, 0. `US-076-coin`, whose body compares `random 1` with 0.5, exited 1 with `repeats` `flaky`; its line read, for instance, `flaky   US-076-coin in sp: 3 pass, 7 fail, 0 invalid, 0 not run`, the counts of its result file, and nine execution lines carried `#2` to `#10`.
