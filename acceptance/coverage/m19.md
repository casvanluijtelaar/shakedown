# M19 The first public release: coverage

No release has been published: the tag, the GitHub release, `release.yml` and winget are the owner's steps. The checks judge a release zip built on the test machine from the main checkout at `4431592`: `python tools/package.py --tag v0.1.8`, the workspace version, wrote `target\dist\shakedown-windows-x64.zip` (3.8 MB) and its `.sha256` in 36 s. A "release folder" in the work folder holds the zip, its `.sha256` and `tools/install.ps1`, as `DST-01` says a GitHub release holds them, and `install.ps1` takes it through `SHAKEDOWN_DOWNLOAD`, as `DST-03` and `docs/install.md` give for a mirror or a test. Every install went into a folder of the work folder named by `SHAKEDOWN_INSTALL_DIR`, never `%LOCALAPPDATA%\Programs\Shakedown` or `target\shakedown`.

The M19 run: `python acceptance/run.py --check US-095 --check US-096 --check US-097 --check US-098 --check NFR-LG-04 --check NFR-PT-01 --check "DST-01 tools/package.py" --dist <main>\target\dist`, once, from 08:09Z to 08:17Z on 2026-11-22 (7 min 13 s, four singleplayer starts, none lost to `Error 20 reading file`). 19 of 20 passed. The one failure, `US-098 ... the one-line route refuses, names each shakedown.exe ...`, was the harness's: the refusal is a PowerShell error record, which PowerShell wraps at its host's width also when its output goes to a pipe, so each command ran over two lines and the check read only the first. The check now compares the text with spaces, line breaks and quotes left out, and the US-098 checks have a part of their own; the two US-098 checks ran once more, alone, from 08:17Z to 08:20Z, and passed. So every M19 check passed once, with no finding.

## The clean shell

The owner's decision: the clean machine is this machine in a shell with Rust, HEMTT and Python removed from `PATH`. Every command the M19 part starts, `powershell.exe`, `cmd /c shakedown ...` and the session's commands, gets the `PATH` a new shell gets from the registry, the machine's entries and then the user's, read again after each install, with every folder holding `cargo.exe`, `rustc.exe`, `rustup.exe`, `hemtt.exe`, `python.exe`, `python3.exe`, `pythonw.exe` or `py.exe` left out, and no `PYTHON*`, `CARGO*`, `RUSTUP*` or `SHAKEDOWN*` variable. In it `cargo`, `rustc`, `hemtt`, `python`, `python3` and `py` were all not found. The execution policy is the user's `RemoteSigned`: the script ran as `powershell -NoProfile -File install.ps1`, a file made on this machine, and by `powershell -NoProfile -Command "irm http://127.0.0.1:<port>/install.ps1 | iex"` from an HTTP server inside the harness's own process, stopped when its part ended.

The user's registry `PATH` (a `REG_SZ`) was saved before the round and before each install, and put back exactly, with its value kind, after each, with the change broadcast as Windows' own dialog does. After every part it matched what was saved, and after the round it matches the copy saved before the round.

## Requirements beside the stories

- **`NFR-LG-04`**: `LICENSE` holds the GPL version 2 text and the grant of later versions, and the zip's `LICENSE` is the repository's. `cargo metadata` gives `GPL-2.0-or-later` for every crate of the workspace: `shakedown`, `shakedown-protocol`, `shakedown-ext` and `skdfx-ext`. `THIRD-PARTY-LICENSES.txt` (1.1 million characters) names each of the 87 packages that `cargo metadata` resolves as normal dependencies of `shakedown` and `shakedown-ext` for 64-bit Windows, proc macros left out, `rmcp` among them, and holds the Apache-2.0 text. That the text of each is that package's own licence and notices was not judged.
- **`NFR-PT-01`**: `shakedown.exe` and `shakedown_x64.dll` of the zip are PE files for x64. `cargo check --release --target x86_64-unknown-linux-gnu -p shakedown-ext -p shakedown-protocol` exits 0. Which other parts "need no Windows API" the requirement does not list, so only those two crates were checked.
- **`DST-01`**: `tools/package.py --tag v9.9.9` exits 1 in under a second with `the tag v9.9.9 does not match the workspace version 0.1.8 in Cargo.toml (want v0.1.8)` and leaves `target\dist` as it was. That `release.yml` then publishes nothing is the owner's to see.
- **The README**: says what Shakedown is, installs it by winget, by the one-line script and by the zip, checks with `shakedown version`, names GPL version 2 or later and says the game's EULA binds its use. Its quickstart check passed after each route (`US-095` 3).
- **`NFR-LG-03`**: not driven. Whether code was copied from another project can only be read in the source, which the tester does not open.
