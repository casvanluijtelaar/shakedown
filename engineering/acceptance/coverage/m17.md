# M17 ACE interaction: coverage

The M17 run: `python acceptance/run.py --check US-089 --check US-090`, once, as the owner set for this round, from 07:17Z to 07:20Z on 2026-11-22 (3 min 42 s, three game starts), at the checks' commit `2fde8ec`. The framework was the install in `target\shakedown\` of the main checkout; `shakedown version` prints `0.1.8`. ACE3 was the Steam Workshop's item 463939057, which every machine reported as `3.21.2.113`. Steam ran logged in and no start was lost to `Error 20 reading file` or `DEF-28`. 6 of 6 passed.

## How the checks drive it

The harness's project `m17` holds the five checks of `acceptance/m17/` and a `shakedown.toml` naming CBA, both fixtures and ACE (`patch = "ace_main"`), with the setups `ded-ace` (a dedicated server with two clients loading all four), `sp-ace` (singleplayer, the same) and `sp-noace` (singleplayer, CBA and both fixtures). One `run --setup <setup> --json` per setup, each starting and stopping its own session:

- **`ded-ace`** (87.6 s with its start): `US-089-crate` creates `skdfx_Crate`, places `p1` 2 m from it, calls `["p1", _crate, ["ACE_MainActions", "skdfx_aceOpen"]] call skd_fnc_useAceAction`, then expects `skdfx_open` on the crate on every machine and the server's `skdfx_openCount` one higher: pass. `US-089-self` calls the self action with the target `"p1"` and expects `skdfx_aceSignals` on `p1`'s unit one higher on every machine: pass. `US-090-missing` asks for `skdfx_noSuchAction` under `ACE_MainActions` with a ceiling of 3 s: `fail` / `assertion` 3.6 s after the check started (the reset before it included), `reason.machine` `p1`, the message `"ACE_MainActions" has no action "skdfx_noSuchAction"; the actions there are: "ACE_OpenBox", "skdfx_aceOpen", "ace_dragging_drag", ...`.
- **`sp-ace`** (42.2 s): `US-089-self` passes in singleplayer; `US-090-never` asks for `skdfx_aceNever` with a ceiling of 3 s: `fail` / `assertion` at 3.4 s, `the condition of "ACE_SelfActions > skdfx_aceNever" was false.`
- **`sp-noace`** (29.8 s): `US-090-noace` ends `fail` / `check-error` 0.4 s in: `ACE is not loaded on p1 (no ace_interact_menu), so it has no ACE action "ACE_SelfActions > skdfx_aceSignal". Add ACE to the setup's mods, or use no ACE action in this setup.`

The result files of `ded-ace` and `sp-ace` record, for `server`, `p1` and `p2` and for singleplayer `p1`, the mod `ace` with patch `ace_main` and version `3.21.2.113` (US-089 3). Every result file is valid against `result.schema.json`. The resets between the ACE checks, which call ACE medical's full heal (`INT-ACE-02`), all completed.
