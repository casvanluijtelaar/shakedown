# M14 Reload without a game restart: report

M14 is complete, at version `0.1.4`. Exit criteria 1 to 4 are met. On 2026-11-23 the owner waived the demo of criterion 5, and it was not run.

The M14 build set the workspace version to `0.1.4`. M14 closes after M15 to M19's builds, which raised the workspace version ahead for M19's pre-release, so the binaries built at the close commit report `0.2.0-rc.1`, not `0.1.4`.

## What it built

| Part | Where | What it does |
|---|---|---|
| The level `mission-restart` | `crates/shakedown/`, `spec/contract/cli.md`, `spec/contract/mcp-tools.md` | `RLD-02`: a changed `.sqf` of a watched mod that the build already holds reloads by a mission restart; new and deleted files, `config.cpp` and other kinds of file stay `game-restart`, and a reload applies the highest level any file needs. |
| The release files | `crates/shakedown/` | `RLD-07`: one 8 MiB file and 80 junctions to its folder in `skd_release` of the game folder, made by the first reload that needs them and kept; every machine reads the 80 paths so the game lets go of the files it held. |
| The reload at that level | `crates/shakedown/`, `addon/` | `P-08`, `RLD-06`: the read of the release files, a check that no game process holds a changed file, the mod's `rebuild`, the mission restart (the server, or `p1` in singleplayer, keeps its process), and after it each `CfgFunctions` function whose file changed recompiled on every machine, with `reload: partial` (`RLD-05`, `DM-08`). |
| The fallback | `crates/shakedown/` | `US-082`, `RLD-03`: a file still held after the second read makes the reload a game restart, naming the file and the machine whose process holds it, found through the Windows Restart Manager. |
| A held file on demand | `fixtures/`, `spec/contract/fixture-mod.md` | `FIX-04`: `skdfx_fnc_holdFile` has the fixture's extension hold a file open in the game process. |
| The docs | `docs/reloading.md` | The reload at level `mission-restart`, the release files, the fallback and `partial`. |

## The spike

`SPK-19` passed ([research 31](../../research/31-spike-reload-release.md)): every machine that reads 640 MiB of other loose files through file patching lets go of the files it held, and a mission restart then takes a changed `.sqf`, 10 of 10 on a dedicated session with two clients and 10 of 10 in singleplayer. `RLD-02`, `RLD-05`, `RLD-06`, `RLD-07`, `P-08`, `FIX-03`, `FIX-04`, `NFR-PF-01`, `NFR-PF-02`, `US-054`, `US-055` and `US-057` were edited in place to it.

## Tests

## Decisions written into the spec

- `RLD-02`: a changed `.sqf` the build already holds is level `mission-restart`, with the reason that the game is made to let go of the file and a mission restart compiles it again.
- `RLD-07`, `P-08`: the release files and the steps of the reload at that level; `RLD-03`: the fallback to `game-restart` naming the file and its holder.
- `RLD-05`, `DM-08`: `CfgFunctions` functions recompiled after each mission restart until a game restart, and `reload: partial` for a check after such a recompile.
- `NFR-PF-02`: the `mission-restart` targets from M14's reloads, 20 s in singleplayer and 90 s on a dedicated session with two clients.
- `FIX-03`, `FIX-04`: the fixture's reload targets may change during a reload's `rebuild`, and `skdfx_fnc_holdFile`.

## The demo

The milestone's demo: a changed `CfgFunctions` function of arma-grappling-hook reloaded at level `mission-restart` into running `sp-cba` and `dedicated-cba` sessions, with a check of the mod rerun on each. The owner waived it on 2026-11-23, and it was not run. The acceptance round drove the same reload on `@skd_fixture_cba`.

## Acceptance

The M14 round, on 2026-11-18 at `efe84ef`, passed 45 of 45 and the 108 runs of the earlier reload checks, and 4 of 4 of the library reload checks, with no finding.

## Left out

- G2's 30 s for mod code on a dedicated session (`DEF-32`, no milestone yet): the mission restart starts new clients.
- A rebuild that knows its reload level (`DEF-33`, no milestone yet).
- `BIS_fnc_recompile` mid-mission (`SPK-09`), `DEF-21`'s second and third options, and the exact size of other reads that frees a file.
- Not driven by the round: the first making of the release files on a game folder without them, a file held by a client on a dedicated session, and a `config.cpp` among the changed `.sqf` files.
