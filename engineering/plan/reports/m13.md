# M13 Every setup, repeated: report

M13 is complete, at version `0.1.3`. Exit criteria 1 and 2 are met. On 2026-11-23 the owner waived the demo of criterion 3, and it was not run.

The M13 build did not raise the workspace version, so its binaries reported `0.1.2`; M14's build set `0.1.4`. M13 closes after M15 to M19's builds, which raised the workspace version ahead for M19's pre-release, so the binaries built at the close commit report `0.2.0-rc.1`, not `0.1.3`.

## What it built

| Part | Where | What it does |
|---|---|---|
| Every setup in one command | `crates/shakedown/`, `engineering/spec/contract/cli.md`, `engineering/spec/contract/mcp-tools.md` | `RUN-07`: `run --each-setup`, and `run_start` with `each_setup`, run each setup's checks in a session of its own, one after the other in the project file's order, with one result file per setup; it is refused while a session runs. |
| A setup that cannot start | `crates/shakedown/` | `US-075`: a start that is refused or fails lists that setup's checks `not-run` / `session-failed` in a result file of its own, and the next setup still runs. |
| Repeats and their summary | `crates/shakedown/`, `result.schema.json` | `OUT-02`, `DM-09`: `run --repeat <n>` runs each check n times and reports per check and setup the counts of `pass`, `fail`, `invalid` and not run, and whether it is steady or `flaky`; repeats a broken session never started are `not-run` / `session-broken` and the summary counts only the repeats that ran. |
| Slow steps and checks | `crates/shakedown/`, `result.schema.json` | `TIM-01`, `CFG-01`: the project key `slow_step` (10 s by default) flags a step that takes longer, and a check that takes more than half its timeout is flagged `slow`; a `slow_step` that is not a number of seconds above 0 stops `list` and `run` with exit 3. |
| The docs | `docs/every-setup-and-repeats.md`, `docs/project-file.md`, `docs/agent-tools.md`, `docs/unattended-runs.md` | Running every setup, repeats and flaky checks, slow steps. |

## Tests

## Decisions written into the spec

- `RUN-07`, `engineering/spec/contract/cli.md` and `engineering/spec/contract/mcp-tools.md`: `run --each-setup` and `each_setup`; a setup's run holds the checks that name it, and a failed start costs only that setup's checks.
- `OUT-02`, `DM-09` and `engineering/spec/contract/result-file.md`: `run.repeat`, each execution's `repeat`, and the `repeats` summaries with their `setup`, also on `run_result`.
- `TIM-01`, `CFG-01`: the project key `slow_step`, `run.slow_step_s`, and the `slow` flag on steps and checks.

## The demo

The milestone's demo: `shakedown run --each-setup --repeat 5` on arma-grappling-hook's suite over `sp-cba`, `sp-cba-ace` and `dedicated-cba`. The owner waived it on 2026-11-23, and it was not run. The acceptance round drove every setup, repeats and slow steps on the fixtures.

## Acceptance

The M13 round, on 2026-11-16 at `3a7602a`, passed 60 of 60 and the 87 checks of its rerun, with no finding.

## Left out

- Running two setups' sessions at once, and a slow threshold per step or per check.
- A Ctrl+C or `run_stop` during `--each-setup`, and a nested step flagged slow through its inner step: the docs say them, no story promises them, and the round did not drive them.
