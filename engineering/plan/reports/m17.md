# M17 ACE interaction: report

M17 is complete, at version `0.1.7`. Exit criteria 1 to 3 are met. On 2026-11-23 the owner waived the demo of criterion 4, and it was not run.

The M17 build set the workspace version to `0.1.7`. M17 closes after M18 and M19's builds, which raised the workspace version ahead for M19's pre-release, so the binaries built at the close commit report `0.2.0-rc.1`, not `0.1.7`.

## What it built

| Part | Where | What it does |
|---|---|---|
| ACE interaction by path | `addon/`, `spec/contract/check-api.md` | `ACT-04`, `INT-ACE-03`: `skd_fnc_useAceAction [machine, target, path]` makes a player use an ACE interaction action on an object or on itself, found by its path of action names, through ACE's own key-up code, pinned to ACE3 3.21.2. |
| An action that cannot be used | `addon/` | `US-090`, `DM-04`: a name missing from the path ends the check `fail` / `assertion` listing the actions there, a condition that stays false ends it `fail` / `assertion` saying so, and a setup without ACE ends it `fail` / `check-error`. |
| The fixture's ACE actions | `fixtures/`, `spec/contract/fixture-mod.md` | An ACE action on the crate and two ACE self actions, one whose condition is always false, registered only where ACE is loaded. |
| The docs | `docs/ace-interaction.md`, `docs/check-api.md`, the agent guide | ACE interaction. |

## The spikes

[Research 35](../../research/35-spikes-ace-and-keys.md). `SPK-21` passed: ACE's key-up code runs an action found by its path once when its condition holds and not when it does not, on an object and on the player, in singleplayer and on a dedicated client, 10 of 10. `SPK-11` failed: a key posted to the game's own window reached neither a display-46 key handler nor a CBA keybind, even with the game in the foreground. `ACT-05` is dropped, `US-091` and `US-092` are `deprecated`, and the extension's key call was removed.

## Tests

With the game and ACE3 3.21.2 from the Workshop, after `python tools/install.py`: `cargo test -p shakedown --test m17 -- --ignored --nocapture --test-threads=1`, with `us_089_us_090_act_04_ace_actions_in_singleplayer`, `us_089_us_090_act_04_ace_actions_on_a_dedicated_session` and `us_090_dm_04_an_ace_action_without_ace_is_a_check_error`.

No repeated-demo test was run at the close: no exit criterion of M17 asks for one apart from the demo the owner waived.

## Decisions written into the spec

- `ACT-04`, `INT-ACE-03` and `spec/contract/check-api.md`: `skd_fnc_useAceAction`, through ACE's key-up code, pinned to the ACE3 version `SPK-21` ran on; it checks no distance or line of sight, as ACE's key-up code does not.
- `ACT-05` dropped with `SPK-11`, and `US-091` and `US-092` deprecated with it.
- `spec/contract/fixture-mod.md`: the fixture's ACE actions, registered only where ACE is loaded.

## The demo

The milestone's demo: with ACE on a dedicated session with two clients, `p1` opens the fixture's crate through its ACE action and every machine sees it open; the ACE self action in singleplayer and on the dedicated session; a wrong path, a false condition and a setup without ACE each ending saying which. The owner waived it on 2026-11-23, and it was not run. The acceptance round drove each of these.

## Acceptance

The M17 round, on 2026-11-22 at `2fde8ec`, passed 6 of 6, with no finding.

- The ACE menu's reach, and Zeus and vehicle-seat menus.
