# M19 The first public release: report

M19 is complete, at version `0.2.0`, and with it phase 2. Exit criteria 1, 3 and 4 are met, and criterion 2 for every part that needs no winget. On 2026-11-23 the owner waived the demo of criterion 5, and it was not run.

The release `v0.2.0` is the tag on `56021ef`, which raised the workspace version to `0.2.0`. This close commit changes only documents and is not tagged.

## What it built

| Part | Where | What it does |
|---|---|---|
| The licence | `LICENSE`, every crate's `Cargo.toml` | `NFR-LG-04`: GPL version 2 with the grant of later versions, `license = "GPL-2.0-or-later"` in every crate of the workspace. |
| The package | `tools/package.py` | `DST-01`, `NFR-LG-04`: checks the tag against the workspace version, builds the binary, the extension and the addon, writes `THIRD-PARTY-LICENSES.txt` from `Cargo.lock`, and assembles `shakedown-windows-x64.zip` and its `.sha256`. |
| The release workflow | `.github/workflows/release.yml` | `DST-01`, `DST-02`: on a tag `v<version>`, the tag check, the build on `windows-latest`, a GitHub release (a pre-release for a version with a pre-release part) with the zip, its `.sha256` and `install.ps1`, and for a release whose package is in `microsoft/winget-pkgs`, `komac update` to winget. It runs no game. |
| The install script | `tools/install.ps1` | `DST-03`, `US-097`, `US-098`: downloads and checks the zip, installs into `%LOCALAPPDATA%\Programs\Shakedown`, adds it to the user `PATH` once, and refuses while a `shakedown.exe` of the folder runs. |
| The docs | `docs/install.md`, `README.md` | The three routes, upgrade and removal, what a release holds, the licence, and the install from source last; the README for someone who finds the repository. |

## Acceptance

The M19 round, on 2026-11-22 at `b24b039`, passed 20 of 20 against the locally built zip, with no finding: the zip's files and `.sha256`, the licence and the third-party notices, `install.ps1` as a file and by `irm | iex`, the zip by hand, a reinstall, a corrupt and a cut-off zip refused, and an upgrade refused while a runner and `shakedown mcp` ran, each followed by a passing run.

The full run at the end of phase 2, at `4431592` on 2026-11-22, ran every check of M0 to M18 once in 1 h 31 min: 394 of 410 passed, and every check after one rerun of each failure. The 14 M10 failures were the harness's copy of a relative mod path; the two `US-015` failures of M9 were flaky, ending `invalid` / `unhealthy` on `p1`'s answer time instead of `machine-lost` on `p2`, and both passed on their rerun. There was no finding.

## Not driven

- winget: `winget install --manifest`, `winget install`, `winget upgrade` and `winget uninstall`, and an upgrade by winget while a runner runs. Until microsoft/winget-pkgs#487410 merges, `winget install casvanluijtelaar.Shakedown` in the README and `docs/install.md` finds no package.
- An upgrade from one published release to a newer one: only one release exists. The round changed an install and ran the script again instead.
- The default install folder `%LOCALAPPDATA%\Programs\Shakedown` in the round, which used `SHAKEDOWN_INSTALL_DIR`; the owner's install of rc.1 used the default.
- A download that fails, as against one that arrives damaged.

## Left out

- macOS and Linux binaries and an `install.sh`, code signing, and a launcher like HEMTT's, as the milestone says.
- The documented one-line install takes its script from `releases/latest`, so it installs no pre-release while only pre-releases exist, and with `SHAKEDOWN_VERSION` set it still runs the latest release's script; rc.1 was installed with the tag's own script URL, which `docs/install.md` does not give (`DEF-35`, open).
- `release.yml`'s `komac update` for the version after `0.2.0` keeps `ArchiveBinariesDependOnPath` only if Komac carries it from the merged manifest, which nothing has shown yet (`DEF-36`, open).
- `DEF-30`, which M19 took up, is `done`.
