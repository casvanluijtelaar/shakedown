# M17 ACE interaction

## Goal

Act through the player path the MVP left out. arma-grappling-hook puts every action of its into ACE interaction when ACE is loaded (its `CTL-02`, `CMP-01`), which its own M10 milestone delivers, and a check of that promise has to reach the action as an ACE player does. Whether a key passes through to the game, as its `CTL-01` promises, stays read by calling the keybind's code (`DEF-26`): `SPK-11` found that a key posted to the game's window does not reach the game, so real key input (`ACT-05`) is dropped.

## Demo

With ACE loaded, on a dedicated session with two clients, `p1` opens the fixture's crate through its ACE interaction action and the server and both clients see it open; `p1` uses the fixture's ACE self action, in singleplayer and on the dedicated session; a wrong path, a false condition and a setup without ACE each end the check saying which. arma-grappling-hook has no ACE action until its own M10, so the demo runs on the fixture (rule 4 of the plan), and the same function serves that mod's checks once its actions exist.

## Stories

- `US-089` (feature) Make a player use a mod's ACE interaction action
- `US-090` (error) The ACE action cannot be used

`US-091` and `US-092`, real keys, are deprecated with `ACT-05`.

## What it builds

- `skd_fnc_useAceAction`, ACE interaction by path (`ACT-04`), in the check API contract and the addon, through ACE's key-up code and pinned to ACE3 3.21.2, the version `SPK-21` ran on (`INT-ACE-01`, `INT-ACE-03`).
- Fixture behaviours: an ACE action on the crate and two ACE self actions, one whose condition is always false, registered only where ACE is loaded.
- `docs/`: ACE interaction.

## Spikes

- **`SPK-21`**, whole, ran before the ACE work and passed: ACE's own key-up code runs an action found by its path once when its condition holds and not when it does not, on an object and on the player, in singleplayer and on a dedicated client, 10 of 10 (research `35-spikes-ace-and-keys.md`).
- **`SPK-11`**, whole, ran before the key work and failed: a key posted to the game's own window reached neither a display-46 key handler nor a CBA keybind, even with the game in the foreground (research `35-spikes-ace-and-keys.md`). `ACT-05` is dropped, `US-091` and `US-092` are `deprecated`, and the milestone delivers the ACE work alone.

## Exit criteria

1. `US-089` and `US-090` pass their acceptance criteria on a Windows machine with Arma 3.
2. The spikes' results are in `engineering/research/`, and the spec is edited in place to what they found.
3. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
4. The owner has run the demo on a Windows machine with Arma 3.

## Left out

- `skd_fnc_pressKey` returning the keybind's value (`DEF-26`): without real keys the documented way round stays.
- The ACE menu's reach: ACE's key-up code checks no distance or line of sight, so neither does `skd_fnc_useAceAction`; a check that promises the player can reach an action asserts the distance itself.
- Zeus and vehicle-seat menus: the path starts at an object's or the player's own menu.
