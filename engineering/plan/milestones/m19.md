# M19 The first public release

## Goal

Make Shakedown installable without its source, as `DEF-30` asks: a test author on arma-grappling-hook, or on any mod, installs a released version the way they install HEMTT. The repository is public with no licence, so the licence comes first. This is phase 2's last milestone and its release, 0.2.0 (rule 17 of the implementation plan). It changes no code of the runner, the extension or the addon, so it is specified beside M16 to M18 and built after M18.

## Demo

On a Windows machine in a shell with no Rust, HEMTT or Python on `PATH`, `winget install` from the release's manifest gives a `shakedown` on `PATH`, `shakedown version` prints 0.2.0, and `shakedown run --setup sp` in a project with one passing check, such as the README's quickstart, gives `pass`. The same zip through the one-line script refuses an upgrade while that session's runner runs.

## Stories

- `US-095` (feature) Install a released Shakedown without building it
- `US-096` (feature) Upgrade or remove an installed Shakedown
- `US-097` (system fail) A corrupt or cut-off download is refused
- `US-098` (mistake) An upgrade while Shakedown runs

## What it builds

- `LICENSE` with the GPL version 2 text and the grant of later versions, and `license = "GPL-2.0-or-later"` in every crate of the workspace (`NFR-LG-04`).
- `THIRD-PARTY-LICENSES.txt`, made at release time from `Cargo.lock` for the packages compiled into `shakedown.exe` and `shakedown_x64.dll`, by `tools/package.py`, which also checks the tag against the workspace version, builds the binaries and the addon, and assembles the zip and its `.sha256`.
- `.github/workflows/release.yml`: on a tag `v<version>`, checks the version against `Cargo.toml`, builds on `windows-latest` with cargo and HEMTT, assembles the zip, its `.sha256` and `install.ps1` into a GitHub release, and, for a version with no pre-release part, submits it to winget with Komac (`DST-01`, `DST-02`).
- `tools/install.ps1` (`DST-03`, `US-097`, `US-098`).
- The workspace version raised to 0.2.0 at the close.
- `docs/install.md` with the three routes first and the install from source last, and the root `README.md` written for someone who finds the repository: what Shakedown is, how to install it, the licence, and that the game's EULA binds its use.

## Exit criteria

1. A pre-release tag, such as `v0.2.0-rc.1`, with the matching workspace version, builds a GitHub pre-release as `DST-01` says, and a tag that differs from the workspace version publishes nothing.
2. `US-095` to `US-098` pass their acceptance criteria against that pre-release, on the Windows test machine in a shell whose `PATH` holds no Rust, HEMTT or Python (the owner's decision: the product is designed for a normal Windows machine, and no Windows Sandbox is used); winget installs from the release's manifest with `winget install --manifest` while the package is not yet in `microsoft/winget-pkgs`.
3. The gates of `NFR-MT-03` pass, `release.yml` runs no game, and `docs/` say how to install, upgrade and remove a release.
4. The owner's steps are done: the repository secret `WINGET_TOKEN`, a fork of `microsoft/winget-pkgs`, the push of `v0.2.0`, and the first winget submission of `casvanluijtelaar.Shakedown` with `komac new`, open as a pull request. Its merge is up to the winget maintainers and does not hold the milestone.
5. The owner has run the demo on the Windows test machine against the 0.2.0 release.

## Left out

- macOS and Linux binaries and an `install.sh`: on those systems the binary is built with cargo (`NFR-PT-02`), and no user has asked for a download yet.
- Code signing: Windows SmartScreen warns on the first run of the unsigned binary, as it does for HEMTT. It waits until users show it matters.
- A launcher like HEMTT's, which would save a winget pull request per version; it waits until releases come often enough for that to cost.
