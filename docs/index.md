# Documentation

* [Installing Shakedown](install.md) - What Shakedown needs on the machine, how to install a release with winget, the one-line script or the zip by hand, how to upgrade and remove it, what a release holds and its licence, the files the runner keeps for itself, and how to build and install from source.

* [Script errors, logs and evidence](script-errors-and-logs.md) - How a script error on any machine fails a check and is traced to its machine and step, how a check expects an error, what each machine's log in the run folder holds and how to read it with logs, the evidence a failed check keeps, and how the Steam account is kept out of all of it.
* [Asking a running game](asking-a-running-game.md) - How to run code on a machine of a running session, wait for a condition, try an assertion live, inspect a machine and list the script errors it caught, from the command line, and what status shows of a start that failed.

* [ACE interaction actions](ace-interaction.md) - How a check makes a player use a mod's ACE interaction action, on an object or on itself, by its path of action names with skd_fnc_useAceAction, how to find an action's path, what the function does through ACE's own key-up code, how it fails, the ACE version it is pinned to, and why a check cannot send a real key to a game window.
* [Handing over to a manual tester](handing-over.md) - How a check sets up a situation and hands it over to a person with skd_fnc_handOver, what the person finds on screen and in the command's output, how the session stays up for them, how the session is taken back, and what a hand over to a machine with no screen does.
* [Agent tools](agent-tools.md) - How an AI agent drives Shakedown through the shakedown MCP server - the project's .mcp.json, every tool and its command line twin, the rules every tool keeps, the agent's workflow for a session and a run, the error codes, and the text the guide tool returns.
* [When a start is refused or fails](starting-and-failed-starts.md) - What session start checks before any game process starts and how it names every gap at once, how to pin a mod's version so a Workshop update stops the start, what happens to a start whose client hangs, where the reason of a failed start is kept, and what happens to a client that code sends to another server.
* [When a client or the runner ends](sessions-and-the-runner.md) - What happens to a session when the command or the AI agent session that started it ends, when the runner itself dies, and when a command cannot reach the runner, how to end a runner that cannot be reached, and how the runner keeps control to the local user and records every piece of code sent to the game.
* [Running a suite unattended](unattended-runs.md) - How to run the whole suite with one command that starts and stops its own session, how to stop a run by hand from the console, the command line or an AI agent, the runner ceiling that stops a run that hangs, and how to read the result file of a stopped run.
* [Every setup, repeats and slow steps](every-setup-and-repeats.md) - How one command runs a suite in every setup its checks name, one session after the other, what happens when a setup's session does not start, how to repeat a check and read its spread of outcomes and a flaky summary, what becomes of repeats when the session breaks, and how slow steps and slow checks are flagged.
* [Outcomes and a broken session](outcomes-and-broken-sessions.md) - What pass, fail and invalid mean and every reason kind each carries, which cause decides when several come in one check, how the runner sees a machine that stops answering, a process that ends or crashes, a game clock that stops and a machine whose frame rate collapses or whose answers lag, what each machine's health in status shows, what a lost machine leaves in the result file, and how to find out what went wrong in a broken session without a restart.
* [Porting an existing suite](porting-a-suite.md) - How to move a mod's existing checks, driven by PowerShell scripts that start the game and read its RPT, to Shakedown - what each part of the old suite becomes, the order of the work, how to rewrite one check, and how to show that the port reaches the same verdicts.
