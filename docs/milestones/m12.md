# M12 Shared helpers and mod events: report

M12 is complete, at version `0.1.2`. Exit criteria 1 to 3 are met. On 2026-11-23 the owner waived the demo of criterion 4, and it was not run.

The M12 build set the workspace version to `0.1.2`. M12 closes after M15 to M19's builds, which raised the workspace version ahead for M19's pre-release, so the binaries built at the close commit report `0.2.0-rc.1`, not `0.1.2`.

## What it built

| Part | Where | What it does |
|---|---|---|
| The library folder | `addon/`, `crates/shakedown/`, `spec/contract/check-api.md` | `API-06`: every `.sqf` file of `tests/_lib/`, or the folder the project key `lib` names, is compiled on every machine after the mission starts and after each reload, as `skd_lib_<file>`; `list` and `run` take no file of it as a check. |
| A library file that does not compile | `addon/`, `crates/shakedown/` | `US-071`: every check ends `fail` / `check-error` with no step run, naming the file, the line and the engine's message, until the file is fixed and reloaded. |
| A reload of the library | `crates/shakedown/` | `RLD-01`, `RLD-04`: a changed library file is reload level `none`, read again on every machine with no game restart. |
| Recorded events | `addon/`, `spec/contract/check-api.md`, `spec/contract/result-file.md` | `EVT-01`: `skd_fnc_record` records a CBA event or a mission event on chosen machines, `skd_fnc_events` reads them, and `skd_fnc_waitEvent` waits for one with a ceiling; the handlers are removed at the check's end and the events go into the result file. |
| An awaited event that never comes | `addon/` | `US-073`: the wait ends `fail` / `wait-ceiling` with what each machine recorded; a wait on a machine that does not record the event is a `check-error`. |
| Loopback-only ports | `crates/shakedown/` | `NFR-SC-01`, `SES-03`: the session's game ports are read from the system's UDP table and every listening socket binds `127.0.0.1`, so `shakedown.exe` raises no firewall prompt. |
| The docs | `docs/check-api.md`, `docs/project-file.md`, `docs/reloading.md`, `docs/porting-a-suite.md` | Shared helpers, the `lib` key, recorded events, and where a ported suite's shared library and event lists go. |

## Decisions written into the spec

- `API-06`, `CFG-01` and `spec/contract/check-api.md`: the library folder `tests/_lib/` by default, the project key `lib`, one global `skd_lib_<file>` per file, compiled on every machine after each mission start, game restart, join and reload.
- `EVT-01` and `spec/contract/check-api.md`: `skd_fnc_record`, `skd_fnc_events` and `skd_fnc_waitEvent`, with recorded events in the result file in wall-clock order.
- `P-06`, `MCH-01`: the unit a client left behind stays as a body until the next reset deletes it (`m12-1`).
- `NFR-SC-01`, `SES-03`: every socket the framework listens on binds loopback only, and a free game port is read from the system's tables.

## The demo

The milestone's demo: arma-grappling-hook's rope checks with the rope kit in `tests/_lib/` and event lists from recorded `agh_holderChanged` events, in `sp-cba` and `dedicated-cba`. The owner waived it on 2026-11-23, and it was not run. The acceptance round drove the library and the recorded events on the fixtures.

## Acceptance

The M12 round, on 2026-11-16, passed every M12 check 3 of 3 and raised one finding, `m12-1`, from M11's dedicated part: the reset after a client was joined again by the restore failed once in four runs on that client's position. The developer had the server record the unit a client leaves behind, so the next reset deletes it, and the tester verified it, 51 of 51 with `--repeat 3`. The verify round also passed the 34 earlier checks of the loopback-only ports and the reset, and a new check that no `shakedown.exe` listens off `127.0.0.1`.

## Left out

- `skd_fnc_pressKey` returning the keybind's value (`DEF-26`, no milestone yet), and engine events on objects.
- Parts of `API-06` and `EVT-01` no story criterion names, listed by the round and not deferred: the library compiled after a mission restart, a game restart and a join, a library file name outside letters, digits and `_`, a `lib` folder that does not exist, `skd_fnc_record`'s own failures, the `after` argument of `skd_fnc_waitEvent`, recording an event twice, and event names matched without regard to case.
- From the verify round, not deferred: a start refused because a game port is held, and a check that no unit a client left behind remains after the next reset beyond the reset's own verification.
