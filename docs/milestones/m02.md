# M2 Dedicated sessions: report

M2 is built and its framework-side exit criteria are met on the test machine. It stays `in-progress` until the test developer's acceptance round and the owner's demo (exit criterion 6).

## What it built

## Spikes

Results in [research/24-spikes-dedicated.md](../../research/24-spikes-dedicated.md).

- `SPK-01`, server, client and headless client: passed. 100 of 100 round trips on each; 95th percentile 44.1 ms on the server, 16.8 and 16.9 ms on the clients, 43.2 ms on the headless client; no 301 warning in any RPT. No fallback.
- `SPK-03`, server, client and headless client: passed. Every extension read the four variables; no token on any command line. No fallback.
- `SPK-04`, dedicated half: passed. 21 of 21 checks saw the start state on every machine, in each of the two runs after two fixes the first run found; resets 0.44 to 1.50 s over 63, mean 0.69 and 0.76 s. No fallback; nothing is left for `@reset mission`.

Peak memory seen with the server, two game clients and a headless client up: 12,287 MB in use of 16 GB, 6,822 MB of it in the four game processes.

## Decisions written into the spec

- `P-02` step 5: the clients and headless clients start once the server is ready. Step 7: the baseline waits for a settled animation state, a machine without a player for the mission time; `ready` carries the baseline. Step 8: which machine a failed start names.
- `P-03` step 1 and step 6: the `route` request and its `routed` answer; polls on another machine, streamed at most one value every 0.05 s.
- `P-06` and `RST-02`: the reset in four phases on every machine at once; each machine deletes what its own recorder saw and sets the server's baseline date and weather itself; the verification holds once each player has stood within 2 cm for 0.3 s.
- `RST-05`: on a dedicated session the body of a respawned player is deleted, found through `EntityRespawned`.
- `SCN-03`: the date and weather are broadcast by setting them on every machine.
- `INT-AR-05`: the server's passwords are random values of their own, not parts of the session token, since clients take the password on their command line.
- `INT-AR-06`: every process of a dedicated session loads `@shakedown` through the junction; a junction to another folder is re-pointed.
- `INT-AR-09`: the server finds a client by the profile name in `getUserInfo`'s fourth element and reads its state from the seventh.
- `API-01` and the check API: `@setups` names only declared setups (`DEF-06`, now `done`); `player` in a dedicated body is `objNull`; `skd_fnc_player` by name; where `skd_fnc_useAction` fires; `reason.machine` of `skd_fnc_expectEach` and `skd_fnc_expectAgree`.
- `NFR-PF-03` and `NFR-PF-04` carry their measurements.

## The demo

From the repository root, with Steam running and logged in, no game running, and someone connected to the machine's desktop so the client windows render:

```
python tools/install.py
cd e2e\grappling-hook
..\..\target\shakedown\shakedown.exe session start --setup dedicated
..\..\target\shakedown\shakedown.exe run US-009-dedicated-freed-rope
..\..\target\shakedown\shakedown.exe session stop
```

The start takes about 45 s and opens two game windows, titled `Arma 3 - p1 (<session id>)` and `Arma 3 - p2 (<session id>)`; the server runs in a console window. What to look for in `p1`'s window: `p1` on top of three stacked containers, a rope going down their south side, `p1` taking it and dropping to the ground at once. In `p2`'s window the same rope and `p1` falling, seen from beside the stack.

## Left out

- A machine that stops answering or crashes during a check (M9): a routed order that gets no answer ends the check `invalid` / `machine-lost` and breaks the session, but a wait or polled assertion on a machine that stopped answering ends at its in-game ceiling as `wait-ceiling` or `assertion`, not as `machine-lost` (`DM-07`).
- Script errors on any machine (M3), `@reset mission` and every mission restart (M6), the run record and recovery (M5).
- Redaction of Steam names in a failed session's `rpt_tail` (`LOG-02`, M4).
- The `reset` refusal on a broken session names a `game-restart` reload, which is not built yet (M6).
- Vehicle randomisation in `skd_fnc_create` stays `DEF-07`.
