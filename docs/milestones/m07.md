# M7 Reload inside the mission: report

M7 is complete, at version `0.0.8`. Exit criteria 1, 2 and 4 are met, with the Rust jobs of GitHub Actions failing as criterion 4 says. Criterion 3 does not apply. The owner waived the demo of criterion 5, and it was not run.

## What it built

| Part | Where | What it does |
|---|---|---|
| A reload or reset during a run, reload or reset | `crates/shakedown/src/runner/run.rs`, `runner/reload.rs`, `runner/session.rs`, `runner/mod.rs` | `RLD-01`, `US-058`: refused with exit 4 and `session-busy`. During a run the refusal names the run, its progress and `shakedown run stop`, for the whole run, also when a check of it breaks the session. During a reload it names the reload by its id and level (`m07-1`). A run starts by an atomic move from `ready` to running, with its progress set under the same lock. |
| A finding's checks rerun after a reload | `runner/run.rs`, the end-to-end tests | `US-054`, `RUN-01`: a changed `fn_version.sqf` of `@skd_fixture`, reloaded with no files named, and the checks tagged with a finding rerun by that tag. Each execution after a game restart records `reload` `full`. |
| The docs | `docs/reloading.md`, `docs/sessions-and-the-runner.md` | Which changes reload inside the mission (none of a mod's code, until `DEF-21`), what `partial` means, rerunning a finding's checks, and the refusal during a run or a reload. |

Level A of `P-08`, `BIS_fnc_recompile` with `reload: partial` (`RLD-05`, `DM-08`), is not built: a recompile inside the mission needs a changed file to reach a running game, which the game's hold on every mod file it has read prevents (`SPK-08`, [research 27](../../research/27-spikes-reload.md)). Until `DEF-21` finds a way round the hold, `US-054` is met by M6's game restart.

## Tests

- **Without the game**: the unit test `us_058_rld_01_a_reload_during_a_run_names_the_run_its_progress_and_run_stop`.
- **With the game**, after `python tools/install.py`: `cargo test -p shakedown --test m07 -- --ignored --nocapture --test-threads=1`:
  - `us_054_us_058_nfr_pf_02_reload_during_a_run_and_rerun_by_finding_in_singleplayer`: a reload refused during a run, then a changed `fn_version.sqf` reloaded and three checks rerun by a finding's tag, 29.4 s from the reload to the last outcome.
  - `us_054_us_058_nfr_pf_02_reload_during_a_run_and_rerun_by_finding_on_a_dedicated_session`: the same with two clients, 50.3 s.
  - Both ask `reset`, `reload` and the `reload` tool during a `game-restart` reload, and expect the reload named (`m07-1`).

## Decisions written into the spec

- `RLD-01`: a reload or a reset asked while a run, a reload or a reset is in progress is refused, naming what is in progress: a reload by its id and level, a run by its id, its progress and `run stop`. `spec/contract/cli.md` gives the messages.
- M7's milestone, `US-054` and `P-08`: level A waits for `DEF-21`; `US-054` is met by a game restart until then.

## The demo

The milestone's demo: with a dedicated session of two clients, the fixture's `fn_version.sqf` changed from `"1"` to `"2"` is reloaded with level `game-restart`. A check tagged with a finding then sees `"2"` on every machine, within `NFR-PF-02`'s target plus 10 s from the reload to its outcome.

The owner waived this demo on 2026-11-13, and it was not run. The acceptance round's `US-054` checks drove the same chain in the demo's session, `rld7`, three times.

## Acceptance

The test developer's round wrote one finding, for the developer. In `m07-1`, a reset, a reload or the `reload` tool refused during a reload said the session was busy with "a reload or a reset", not which. The session records what it is busy with as it enters `reloading`, and the refusals name it. The finding is verified, its two checks 6 of 6, 3 of 3 in each setup.

The M7 round, against the framework from `25227a3`, ran the 20 M7 checks three times in one session of each setup: `rld7`, a dedicated server with two clients, and `rld7sp`, singleplayer, each loading `@skd_fixture` watched in a staged copy with a `rebuild`. 54 of 60 passed; the 6 failures were `m07-1`'s check. The full run before the fix passed 225 of 227, the 2 failures `m07-1`'s. The full run after it, at `b2d48df` against the framework installed from it, passed 227 of 227, the 20 M7 checks among them. The runs are in [the M7 coverage](../../acceptance/coverage/m07.md).
