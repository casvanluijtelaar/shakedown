# M6 Reload by restart: report

M6 is complete, at version `0.0.7`. Exit criteria 1, 2 and 4 are met, with the Rust jobs of GitHub Actions failing as criterion 4 says. Criterion 3 does not apply. The owner waived the demo of criterion 5, and it was not run.

## The spikes

[Research 27](../../research/27-spikes-reload.md) holds both spikes and the research round that followed `SPK-08`, on Arma 3 2.22.154089 and CBA_A3 3.19.0.

- **`SPK-08` failed.** The game opens every loose mod file it reads shared for reading only. While a process holds the file, it can be neither written nor renamed, and every machine reads the held content, across a mission restart. The game lets go of a file at a time that no wait, flush or setting tried controlled. Once a file was released, a mission restart took the change on every machine, kept processes included, once in singleplayer and once on a dedicated session. That is no promise. CBA's cache is off through the session mission, so `INT-CBA-02` holds and `cba_cache_disable.pbo` is not needed. The owner chose a game restart for every `.sqf` change, made in one step with the mod's `rebuild`: the path the milestone names for a changed file that does not reach a running machine.
- **`SPK-01` across a mission restart passed.** 310 round trips to singleplayer `p1` over 3 mission restarts, 6,025 to a dedicated server over 10 and 602 to a client across 11 processes: none lost and none run twice.

## Decisions written into the spec

- `RLD-02`, `P-08`, `RLD-06`: every `.sqf` change of a mod is level `game-restart`, made in one step: the processes stop, the mod's `rebuild` makes the change while none holds a file, the processes start. `mission` and `mission-restart` are not reload levels; `@reset mission` keeps the mission restart (`RST-06`).
- `RLD-06`, `SES-05` and the project file: a watched mod is loaded from a build of the developer's files, with `source`, `prefix` and a `rebuild` that runs within 120 s.
- `NFR-PF-02`: under 90 s plus the `rebuild` on a dedicated session with two clients, from the ten reloads above. `NFR-PF-01`: G2's 30 s applies to a changed check.
- `INT-CBA-02`: the session mission turns CBA's cache off; `INT-HEM-01` and `INT-AR-04` follow.
- `FIX-03` and the fixture contract: the installed files are changed only while no game process runs, by a `rebuild` from a staged copy.
- `SPK-08` and `SPK-09` in the open questions; `US-054`, `US-055` and `US-057` say what a game restart delivers. M7 says a reload inside the mission waits for `DEF-21`.
- `P-06` step 4: a player's direction is set again while it is more than 1 degree off (`m06-1`).

## The demo

The milestone's demo: with a dedicated session of two clients running arma-grappling-hook, watched in its `addons` folder with `rebuild = "hemtt build"`, a changed function of the mod is reloaded with `shakedown reload`. The reload reports level `game-restart`, the file's reason and the time it took, and the M2 check, rerun, sees the change, with no `session stop` or `session start`.

The owner waived this demo on 2026-11-13, and it was not run. The same chain on the fixture `@skd_fixture_cba` is what the acceptance round's `US-055` checks drove.

## Acceptance

The test developer's rounds wrote one finding, for the developer. In `m06-1`, a reset on a dedicated session failed once in 10 tries on `p2`'s direction, which broke the session for the 34 checks after it. An enemy the check made shot `p2` the moment the reset put it back, and the respawn turned it. The developer's fix sets the direction again in the reset's verify. The finding is verified: its check passed 3 of 3 in one session, nine resets at 0.78 to 0.84 s.

The M6 round at `89efd87`, against the framework from `679c79e`, passed 48 of 48: the 16 M6 checks three times in one dedicated session of two clients and a headless client, with five game restarts, two mission restarts and two ends of `p2` per repeat. The six reloads of changed or named files took 47.2 to 48.1 s, the rebuild included. The full run after the fix, at `d310b44` against the framework from `749d8d6`, passed 200 of 207, all 16 M6 checks among them. Of the 7 failures, 5 were the test machine: a base-game PBO the server could not read, and a client that hung in its start. 2 came from one mistake of a check. All 7 passed when run again. The runs are in [the M6 coverage](../../acceptance/coverage/m06.md).

## Left out

- A reload inside the mission or by a mission restart: the game's hold on the files it read prevents both (`DEF-21`, no milestone yet).
- An order held through a mission restart can keep an MCP tool call past the 60 s of `AGT-03` (`DEF-20`, no milestone yet).
- An enemy a check made can still wound or kill a player while the reset puts it back; the direction is set again, but the damage is not verified (`DEF-22`, no milestone yet).
- The acceptance round did not drive `@reset mission` in singleplayer, which the developer's `SPK-01` test ran, or a `rebuild` that fails or passes its ceiling, which a unit test covers.
