M3 is complete and released as `0.0.4`. Every exit criterion is met.

## Decisions written into the spec

- `P-05`: the context and the start marker come before the reset (step 3); the handler stamps the lead's running step or the step the newest order carried (step 6); an error with no step takes the lead's step at its time, or between steps the last that started (step 7); step 9 cuts each machine's lines, scans them and matches `expectError` blocks.
- `P-06` and `RST-02`: each machine deletes only the recorded entities local to it, and in the verification any that is local to it by then (`DEF-09`); the baseline holds the player's group's behaviour, which the reset restores; the verification puts the player back into the baseline's animation state while it settles; an error in a cleanup is listed with the execution whose reset ran it, without failing it.
- `ERR-01` to `ERR-03`: the stack without variables; the RPT scan per check execution, matched by machine, text and file; an earlier cause decides (`DM-06`); errors during the reset and compile errors of code the check sent are listed but decide no `script-error`.
- `LOG-04`: the marker lines' form, and the RPT's write delay of about 0.5 s.
- `INT-AR-07`: the RPT's error format as 2.22 writes it.
- `INT-STM-04`: a `loginusers.vdf` without `MostRecent`, as Steam writes it on the test machine, gives the entry with the newest `timestamp`.
- The check API: `skd_fnc_expectError`'s `text` is not empty; what an error's text is; when a script error decides and what `evidence.failed_step` is then; no undefined variable is reported in unscheduled code.
- The result file: the errors' range, order, `file` and `stack`, `at` of an RPT error, and `evidence.logs`.
- The fixture contract: `skdfx_fnc_throw` raises nothing in unscheduled code.

## The demo

From the repository root, with Steam running and logged in, no game running, and someone connected to the machine's desktop so the client windows render:

```
python tools/install.py
cd e2e\grappling-hook
..\..\target\shakedown\shakedown.exe session start --setup dedicated
..\..\target\shakedown\shakedown.exe run US-024-dedicated-rope-never-held-by-p2
..\..\target\shakedown\shakedown.exe logs --machine p1 --check US-024-dedicated-rope-never-held-by-p2 --last 20
..\..\target\shakedown\shakedown.exe session stop
```

The run exits 1: `fail` / `assertion` in the step `the server and both clients see p2 holding the rope`, every machine having read `nobody`. The result file under `.shakedown\runs\<run id>\` holds `evidence.observed` for `server`, `p1` and `p2` and `evidence.logs` with a file per machine under `checks\1\`, and any script error the mod raised in `errors`, with its machine and step. A search of the run folder for the Steam ID and the Steam names finds none.

## Left out

- Script errors outside any check, such as those at mission load or between runs, are not kept for `errors` (`ERR-05`, M4, with the `errors` command and tool and the `logs` tool).
- A wait whose condition raises a script error does not end at that evaluation (`OBS-01`); the error fails the check when the body ends (`US-062`, M4).
- The last 10 script errors in `inspect` (`INS-01`, M4).
- A running session's RPTs hold what the game writes, Steam ID included, until the session stops; `logs` redacts what it reads.
- Crash dumps (M9; `DEF-03`).
- The RPT scan copies a `File` line's path as written, so a path with a leading backslash would keep it; the engine wrote none in M3's runs (`DEF-11`, no milestone yet).
- No check has searched what a failed start (`US-004`) prints or keeps for the Steam ID and the Steam name; `US-064` covers a stopped session after a run (`DEF-12`, M4).
