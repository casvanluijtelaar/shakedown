## Spikes

Results in [research/23-spikes-singleplayer-reset.md](../../research/23-spikes-singleplayer-reset.md).

- `SPK-12` passed: objects and groups round-trip by net id in singleplayer.
- `SPK-10` failed as the spec allowed for: the engine runs an action fired with `action ["User", ...]` whatever its condition and radius, so `ACT-01`'s own check is the only one.
- `SPK-05`: without a handler the player's death ends the mission. The first fallback, a `Killed` handler that hands the player a new unit with `selectPlayer`, kept the mission 10 of 10. `endMission` loaded the next `-autotest` entry in 1.6 to 2.0 s, 10 of 10. The second fallback is not needed.
- `SPK-04`, singleplayer half, passed: 20 checks each saw the first one's start state; resets took 0.04 to 0.58 s, mean 0.37 s.

## Decisions written into the spec

- `RST-02`, `P-02` steps 7 and 8, `P-08` step 6: each agent captures the baseline at its mission start once its player stands on the ground, before it reports `ready`; the baseline holds the animation state, which the reset restores (`P-06` step 4).
- `RST-05`, `P-06` step 3: the singleplayer `Killed` handler, and the body it leaves deleted by the reset.
- `ACT-01` and the check API: the engine does not check an action's condition or radius (`SPK-10`); how the condition is evaluated.
- `ACT-03`, `INT-CBA-01` and the check API: `CBA_fnc_getKeybind`'s shape, and the namespace read to list a mod's keybinds, in lower case.
- The check API: what a story or requirement ID looks like in `@check`; the byte order mark; `skd_fnc_onEach` leaves out a machine whose code returned nothing.

## The demo

From the repository root, with Steam running and logged in and no game running:

```
python tools/install.py
cd e2e\grappling-hook
..\..\target\shakedown\shakedown.exe run --setup sp
```

It starts a singleplayer session with CBA and arma-grappling-hook, runs both `US-009` checks, prints `pass` for each and stops the session. To watch it in the game window, start the session first and run the checks as often as wanted:

```
..\..\target\shakedown\shakedown.exe session start --setup sp
..\..\target\shakedown\shakedown.exe run US-009-let-go-key
..\..\target\shakedown\shakedown.exe session stop
```

What to look for: `p1` on top of three stacked containers, a rope going down their south side, `p1` taking it and dropping to the ground at once.

## Left out

- Everything across machines (M2): every function runs on `p1`, the lead; `skd_fnc_useAction`'s stories `US-019` and `US-020`.
- Script errors (M3): a condition or value that raises a script error ends the wait as `check-error` when it returns nothing, not as `script-error`.
- `@reset mission` (M6): a check that asks for it gets the reset in place.
- The `reset` command (M2); `status` and the session's `reason` in it.
- The fixtures' crate, flag, error, version and failure functions, each with the milestone whose story first uses it.
- Vehicle randomisation in `skd_fnc_create`: `DEF-07`.
- The session state `broken` is built only as far as a failed reset or a lost lead need it; the way out is `session stop`.
