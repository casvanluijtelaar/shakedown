# M10 The grappling-hook suite: report

M10 is complete, at version `0.1.0`, and with it phase 1, the MVP of PRD section 9. Exit criteria 1, 2 and 4 to 10 are met, with the Rust jobs of GitHub Actions failing as criterion 10 says. Criterion 3, a reload of a changed arma-grappling-hook function into a running session, was part of the demo and was not run. The owner waived the demo of criterion 11, and it was not run.

## The spike

`SPK-14` passed ([research 29](../../research/29-spike-default-ceilings.md)). An action's effect, a crate's public variable set by the server after `p1` fires its action, reached every machine of a dedicated session with two clients and a headless client within 0.140 s in 100 of 100 runs, the 95th percentile 0.128 s. No passing check of the ported suite or of the framework's own runs came within 5 s of a ceiling: the longest ported check, `US-009-1`, took 51.4 s. `NFR-PF-06` keeps its defaults: wait ceiling 10 s, check timeout 120 s, the runner's grace 10 s, start ceiling 180 s, reset ceiling 15 s. In one `sp-cba-ace` session of the spike, `p1`'s mission time fell below half of real time during `US-064-2`, and the clock watch ended that check and the twelve after it `invalid` / `unhealthy`. The same checks passed 9 of 9 in a second session, so it was counted as a slow environment, as the framework reported it.

## Decisions written into the spec

- `INT-ACE-02`: the reset gives each player ACE's full heal when ACE medical is loaded, and fails naming the ACE version when the heal function is missing.
- `CFG-01` and `spec/contract/cli.md`: a relative path may climb out of the project folder and is resolved before it reaches the game.
- `spec/contract/check-api.md`, `P-06` step 1, `RST-01`: `skd_fnc_cleanup [code, args, machine]`, run on that machine.
- `DM-14`: an object in `args` is looked up once for code that runs once, and before every evaluation for a wait and a polled assertion.
- `NFR-PF-06`: its defaults stand, with `SPK-14` as their source.

## The demo

The milestone's demo: arma-grappling-hook's rewritten M00 checks run with one command per setup, in singleplayer with CBA, with CBA and ACE, and on a dedicated server with two clients, each against one session, and leave one result file per run and nothing running.

The owner waived this demo on 2026-11-13, and it was not run, nor was the reload of exit criterion 3 that belonged to it. The acceptance round ran the same three commands, `shakedown run --setup <setup>` against the ported suite, three times each.

## Acceptance

The port's round wrote five findings, for the developer, all answered and verified: `m10-1`, a relative mod path with `..` made the game exit (fixed); `m10-2`, a cleanup ran on the lead only and could not undo a client's state (fixed); `m10-3`, `skd_fnc_pressKey` does not return what the keybind's code returned (deferred as `DEF-26`, with a way round in `docs/check-api.md`); `m10-4`, checks cannot share helper code (deferred as `DEF-27`, with `docs/porting-a-suite.md` saying each check carries its own copy); `m10-5`, the docs did not say when an object in `args` is looked up (fixed and documented).

The M10 round, against the framework from `780496e`, passed 65 of 65: the findings' checks 12 of 12 and every exit-criterion check 3 of 3, over 18 ported runs, 6 per setup, from the command line and through the agent tools. The full run passed 298 of 300, every check of M0 to M9 among them. The 2 failures came from one execution of arma-grappling-hook's `US-064-1` in the agent's `sp-cba-ace` run, which ended `fail` / `assertion` where the command line's run passed. ACE's leg damage from a 5 m fall is random, and that check's comparison does not always take it in: with ACE it failed 2 of 13, without ACE it passed 8 of 8. It is a flaky check of arma-grappling-hook, not a defect of Shakedown, and it goes to that repository's roles. The runs are in [the M10 coverage](../../acceptance/coverage/m10.md).

## Left out

- Every `should` and `could` requirement, phases 2 and 3.
- The late-joiner cases of `US-009-1-freed` and `MP-01-drawn` (`DEF-04`, no milestone yet).
- `skd_fnc_pressKey` returns `true` once the keybind's code ran, not the code's value (`DEF-26`, no milestone yet).
- Checks cannot share helper code (`DEF-27`, no milestone yet).
- Two gaps the test rounds of M6 to M8 met, deferred in M10: a client that hangs in its start holds `session start` for the whole 180 s ceiling (`DEF-28`), and the `session.json` of a failed start holds no reason (`DEF-29`), both with no milestone yet.
- An agent that is a real Claude Code session drove the suite in no round of M10; the harness spoke the protocol as the agent.
