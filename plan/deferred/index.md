# Deferred work

* [A lost runner.json starts a second runner that ends the live session](01-runner-file-lost.md) - When runner.json is deleted or unreadable while its runner holds a session, the next client starts a second runner, whose recovery ends the first session's game processes.
* [A Steam name that is also a common word is redacted everywhere](02-steam-name-common-word.md) - LOG-02 replaces the Steam account and persona names as whole words, so a name that is also a machine name or a common word would be replaced wherever that word appears.
* [Crash dumps in a run folder are not redacted](03-crash-dump-identity.md) - P-09 copies each crash dump into the run folder as the engine wrote it, and a dump holds process memory that may include the Steam ID and names.
* [Late joiners for the grappling-hook port](04-late-joiners.md) - arma-grappling-hook's dedicated M00 checks include a client that joins late, and joining late is MCH-01, a should, so those cases cannot be ported in M10.
* [A check file saved with a byte order mark has no header](05-check-file-byte-order-mark.md) - A check file that starts with a UTF-8 byte order mark is reported as having no @check line, because its first header line does not read as one.
* [A check whose @setups names an unknown setup is not reported](06-unknown-setup-in-check-header.md) - A check whose @setups names a setup the project file does not declare, such as @setups nosuch, is listed with no error and skipped in every session.
* [skd_fnc_create does not switch a vehicle's randomisation off](07-vehicle-randomisation.md) - SCN-01 promises vehicles created with vehicle randomisation off, but skd_fnc_create makes them with createVehicle as the engine does, so a class that randomises its look on init can differ between runs.
* [skd_fnc_create returns before every machine sees the object in place](08-create-returns-before-machines-see.md) - On a dedicated session skd_fnc_create returns on the server before the other machines see the object at its place, so a check that reads it on a client at once can see no object or the object at the spot it was made.
* [The server logs Object not found after a reset on a dedicated session](09-object-not-found-after-reset.md) - A reset on a dedicated session in which every machine deleted every entity it recorded made the server log Server: Object 2:nnn not found (message Type_189); each machine deletes only the entities local to it, and the line is gone.
* [status drops a failed start at once](10-status-keeps-failed-start.md) - Once a start fails, status no longer shows the session, so a program that only watches status cannot see the failed state or its reason; status is to keep the failed start until the next start or stop.
* [The RPT scan keeps a leading backslash in an error's file](11-rpt-file-leading-backslash.md) - The RPT scan copies a File line's path as the RPT writes it, so a path with a leading backslash keeps it in the result file, while the docs say an error's file has none.
* [No check has searched a failed start for the Steam identity](12-failed-start-steam-identity.md) - US-064 searches a stopped session after a run for the Steam ID and the Steam name; no check has searched what a failed start prints or keeps for them.
* [A cancelled session_start or reset goes on](13-cancelled-session-start.md) - Cancelling the session_start or reset tool call does not stop the start or the reset in the game; only exec, wait_until, expect and inspect stop their work when cancelled.
* [A singleplayer reset after the player died may leave the death camera running](14-death-camera-after-reset.md) - After a reset in which RST-05 replaced a dead singleplayer p1, a later check failed script-error on Undefined variable tsw_camtargetunit errors on p1, so the game's death-camera script may still run after the reset.
* [A start refused for no Steam still starts a runner that lingers](15-refused-start-leaves-runner.md) - A session start refused because Steam is not running starts the runner first, which stays up about 60 s with no session and makes a quick retry run into it.
* [An exec of code that does not compile lists its error twice](16-compile-error-listed-twice.md) - exec of code that does not compile, such as 1 +, gives the engine's Invalid number in expression error twice in what it answers, where one is meant.
* [Where a long tool result goes with no project is not specified](17-long-result-with-no-project.md) - With no project, the MCP server writes a tool result over 20,000 characters to a shakedown-results folder in the system temp folder, and neither AGT-07 nor the MCP contract says so.
* [The code of wait, expect and inspect is not in the audit](18-wait-expect-inspect-not-audited.md) - audit.jsonl records every exec from the command line, MCP and a check, but not the condition of wait or wait_until, the value of expect, or the code inspect sends, though each is code run on a machine.
* [A runner started by WMI once took more than 10 s to write runner.json](19-slow-runner-start-by-wmi.md) - In one of 25 rounds a runner that WMI had created wrote runner.json more than 10 s later, past the 10 s a client waits for it, right after the test had killed the previous runner and its game; it did not recur in 15 rounds with timings.
* [An order held through a mission restart can keep a tool call past 60 s](20-held-order-past-a-tool-call.md) - An exec, wait or inspect sent to a machine whose mission restarts waits for it before its own ceiling starts, so on a dedicated session, where a mission restart takes about 48 s, an MCP call can last longer than the 60 s of AGT-03.
* [A changed mod file reaches a running game only through a game restart](21-reload-without-a-game-restart.md) - The game holds every loose mod file it has read, shared for reading only, until a time nothing tried controls, so every .sqf change reloads by a game restart; what makes the game let go of a file, and the two ways round the hold that research 27 did not run, are left to find.
* [An enemy a check made can still hit a player while the reset puts it back](22-shots-in-flight-during-a-reset.md) - The reset deletes the entities a check made and restores the players in the same phase, so a shot an enemy fired before its machine deleted it can wound or kill a player that is already back at its baseline; the direction is set again, but the damage is not verified and a death after the 1.5 s settle window fails the reset, and a death during the reset was measured to take it to 4.2 and 4.8 s.
* [A reset a stop cut short runs on in the game](23-reset-runs-on-after-a-stop.md) - A run stopped during a check's reset ends that check at once, but the reset phase already sent to the machines, with any cleanup it runs, goes on in the game until it ends or reaches the reset's 15 s ceiling, so a run started right after can meet it.
* [The runner's ceilings count the time the runner itself was paused](24-runner-ceilings-count-a-paused-runner.md) - The heartbeat watch forgives a runner that was suspended, paused in a debugger or starved, but an order's ceiling plus its grace and a check's runner ceiling still count that time, so a check running while the runner is paused can end invalid though every machine answered.
* [The server can log Object not found for a dead player's body the reset deletes while it still falls](25-object-not-found-for-a-falling-body.md) - On a dedicated session the client a dead player's body is local to deletes it in the reset while the body's ragdoll still moves, and about once in 40 kills the server then logs Server: Object n:nnn not found with a message number that varies, naming that body.
* [skd_fnc_pressKey does not return what the keybind's code returned](26-press-key-returns-no-handler-value.md) - skd_fnc_pressKey returns true once the keybind's code ran, so a check cannot read through it whether the key was consumed or passed on to the game, and calls the keybind's code itself with skd_fnc_on to assert that.
* [Checks cannot share helper code](27-shared-helper-code-between-checks.md) - A check cannot load another file and runs no preprocessor, so helper code that many checks use is copied into each, and a change to it is one edit per copy that nothing keeps in step.
* [A client that hangs in its start holds session start for the whole start ceiling](28-hung-client-waits-the-start-ceiling.md) - A game process that runs but never connects during a start is seen only when the start ceiling of 180 s passes, so session start waits the full ceiling before it fails.
* [session.json of a failed start holds no reason](29-failed-start-reason-not-in-session-json.md) - A start that failed, such as one the game ended with Error 20 reading file on a base-game PBO, writes reason null into session.json, so once status no longer holds it nothing says why the start failed.
