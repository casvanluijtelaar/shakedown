# M5 A session that outlives its client

## Goal

Make the session survive the way AI agents are used: a Claude Code session ends and the next one picks the game up where it was. When the runner itself dies, nothing of it is left; when it lives but cannot be reached, the client says so instead of starting a second one; and only the local user's processes with the right token control it.

## Demo

An AI agent in Claude Code starts a dedicated session through MCP; that Claude Code session ends; a new one finds the session `ready` and runs the M2 check against it; then the runner is killed with `taskkill /F` and no game process is left within 10 s.

## Stories

- `US-007` (feature) The session outlives the command or the AI agent session that started it
- `US-035` (system fail) The runner dies
- `US-052` (feature) Only the local user controls the session, and every piece of code sent to it is recorded
- `US-053` (malicious intent) A process without the token cannot run code in the session
- `US-060` (system fail) A new client cannot reach the runner that holds the session

## What it builds

- The runner's detached start under Claude Code (`SES-08`, `INT-WIN-02`), whichever way `SPK-06` shows holds.
- The run record and recovery at every runner start (`STP-03`, `P-12`).
- A runner that does not answer or runs another version (`P-01`): the client's refusal, `status` with the runner `unreachable`, and the `runner-unreachable` code.
- The process check of `SEC-03` from the system's TCP table, the refusals logged in `runner.log`, and `audit.jsonl` (`SEC-04`).
- `docs/`: what happens to a session when its client or its runner ends, and how to end a runner that cannot be reached.

## Spikes

- **`SPK-06`**, whole, runs before the work that depends on it; its pass condition is in `spec/06-open-questions.md`. If it fails: The runner is started as a per-user scheduled task and `INT-WIN-02` is edited. No promise changes.

## Exit criteria

1. `US-007`, `US-035`, `US-052`, `US-053` and `US-060` pass their acceptance criteria on the test machine.
2. `NFR-RL-03` holds 5 times out of 5, and the searches of `NFR-SC-01` and `NFR-SC-03` find nothing.
3. The spike's result is in `research/`, and the spec is edited in place to what it found.
4. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
5. The owner has run the demo on the Windows test machine.

## Left out

A `runner.json` lost while its runner lives (deferred 01).
