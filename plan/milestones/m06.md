# M6 Reload by restart

## Goal

Close the mod developer's loop on arma-grappling-hook. Its functions are CBA `PREP` functions, final once compiled, so a change to them reaches the game only at a mission restart: that level comes first. A change that needs more gets a game restart, a change to a check needs nothing, and every reload says which level it used and why.

## Demo

With a dedicated session of two clients running arma-grappling-hook, a changed function of the mod is reloaded with `shakedown reload`, which reports level `mission-restart`, the file's reason and the time it took, and the M2 check, rerun, sees the change, with no session restart.

## Stories

- `US-011` (feature) A check that changes what a reset cannot name gets a mission restart
- `US-012` (system fail) A mission restart before a check does not bring every machine back
- `US-040` (feature) Edit a check and rerun it with no reload
- `US-055` (feature) Reload a change that needs a mission restart
- `US-056` (mistake) A change that needs a rebuild and a game restart
- `US-057` (system fail) A reload that does not complete

## What it builds

- `reload` (`RLD-01`): the snapshot of each watched `source` folder, the classification of `RLD-02`, the report of `RLD-03`, the rebuild message of `RLD-06`, and its tool. Until M7, a file of level `mission` is applied by a mission restart and the reload's reason says so.
- Level B of `P-08`: in singleplayer through the `-autotest` list, on a dedicated session through `#restart` with fresh client processes; CBA's cache off (`INT-CBA-02`). Level C: every process restarted. A new baseline and snapshot after each.
- `@reset mission` (`RST-06`), and the session state `broken` with the outcomes `reset-failed`, `reload-failed` and `session-broken` (`DM-05`).
- The fixtures' version files and the installed-copy changes of `FIX-03`.
- `docs/`: reloading, its levels, and `@reset mission`.

## Spikes

- **`SPK-08`**, whole, runs before the work that depends on it; its pass condition is in `spec/06-open-questions.md`. If it fails: The session loads CBA's `cba_cache_disable.pbo`, and `INT-CBA-02` is edited. No promise changes. The measured time sets `NFR-PF-02`.
- **`SPK-01`**, its part across a mission restart, runs before the work that depends on it; its pass condition is in `spec/06-open-questions.md`. If it fails: No order is lost or run twice across a restart (`NFR-RL-04`); a failure is fixed in the runner's order bookkeeping. No promise changes.

## Exit criteria

1. `US-011`, `US-012`, `US-040`, `US-055`, `US-056` and `US-057` pass their acceptance criteria on the test machine.
2. The time of a `mission-restart` reload over 10 reloads is recorded, and `NFR-PF-02` is set from it.
3. If M1 took `SPK-05`'s second fallback, the singleplayer half of `US-055` is edited to the game restart that fallback leaves, before the milestone closes.
4. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
5. The owner has run the demo on the Windows test machine.

## Left out

Level A, inside the mission (M7). A reload asked during a run is refused only in M7, with `US-058`.
