# M17 ACE interaction and real keys

## Goal

Act through the two player paths the MVP left out. arma-grappling-hook puts every action of its into ACE interaction when ACE is loaded (its `CTL-02`, `CMP-01`), which its own M10 milestone delivers; and whether a key passes through to the game, as its `CTL-01` promises, is read today only by calling the keybind's code (`DEF-26`), not by a key a player presses.

## Demo

With ACE loaded, `p1` gets on an arma-grappling-hook rope through its ACE interaction action; and a real let-go key sent to `p1`'s window in the background takes `p1` off the rope, while off the rope the same key reaches the game.

## Stories

- `US-089` (feature) Make a player use a mod's ACE interaction action
- `US-090` (error) The ACE action cannot be used
- `US-091` (feature) Send a real key to one game client's window
- `US-092` (mistake) A real key to a machine with no window

## What it builds

- ACE interaction by path (`ACT-04`) in the check API contract and the addon, pinned to the ACE version `SPK-21` ran on (`INT-ACE-01`, `INT-ACE-03`).
- Real key input to one client window (`ACT-05`), if `SPK-11` passes, in the check API contract and the extension.
- Fixture behaviours: an ACE action on an object and a self action; a key handler that consumes one key and passes another.
- `docs/`: ACE interaction and real keys.

## Spikes

- **`SPK-21`**, whole, runs before the ACE work; its pass condition is in `spec/06-open-questions.md`. If it fails: the framework reads the action's condition and statement from the ACE action tree and runs them itself, as `ACT-01` checks an action, and `INT-ACE-03` names the ACE version it reads them from; the stories hold.
- **`SPK-11`**, whole, runs before the key work; its pass condition is in `spec/06-open-questions.md`. If it fails: `ACT-05` is dropped, `US-091` and `US-092` are marked `deprecated`, and the milestone delivers the ACE work alone.

## Exit criteria

1. `US-089`, `US-090`, `US-091` and `US-092` pass their acceptance criteria on the test machine.
2. The spikes' results are in `research/`, and the spec is edited in place to what they found.
3. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
4. The owner has run the demo on the Windows test machine.

## Left out

- `skd_fnc_pressKey` returning the keybind's value (`DEF-26`): with real keys a check reads the pass-through from the game; without them the documented way round stays.
