# M10 The grappling-hook suite

## Goal

Prove the first release where it is meant to be used, and replace arma-grappling-hook's handcrafted PowerShell checks with checks the framework runs. The framework changes here only where the port shows a `must` is not met.

## Demo

arma-grappling-hook's rewritten M00 checks run with one command per setup, in singleplayer with CBA, with CBA and ACE, and on a dedicated server with two clients, each against one session, and leave one result file per run and nothing running.

## Stories

None of its own. It proves the stories of M0 to M9 together, on a real mod.

## What it builds

- In arma-grappling-hook's repository, by its own roles: a `shakedown.toml` with its setups and its M00 checks rewritten as Shakedown checks.
- In this repository: the full heal at a reset when ACE medical is loaded (`INT-ACE-02`), which the ACE setup is the first to need, and fixes for what the port finds.
- `docs/`: porting an existing suite.

## Spikes

- **`SPK-14`**, whole, runs before the work that depends on it; its pass condition is in `spec/06-open-questions.md`. If it fails: The defaults of `NFR-PF-06` are set from the measurement over the ported suite and the framework's own end-to-end checks. Only the numbers change.

## Exit criteria

1. On the one Windows test machine, a test author starts a singleplayer session and a dedicated session with two clients and keeps each alive across many checks (`CR-01`, `CR-02`): each ported run shows one session id, and every machine keeps its start number except across a check with `@reset mission`.
2. The ported checks are written in SQF and build a scene, make a player act through the mod's real path, wait for the outcome and assert it on every machine (`CR-10`, `CR-11`, `CR-12`, `CR-20`, `CR-22`, `CR-50`).
3. A changed arma-grappling-hook function is reloaded into a running session and a ported check rerun on it, without a restart (`CR-03`).
4. Every ported check ends `pass`, `fail` or `invalid` with its reason, its script errors traced to their step, in one result file per run (`CR-23`, `CR-31`, `CR-51`).
5. The ported suite is run once by an AI agent through the MCP tools, with the same outcomes as from the command line, and the agent diagnoses one failing check with `inspect` (`CR-27`, `CR-53`).
6. After every run, nothing of it is left running (`CR-05`).
7. The port: arma-grappling-hook's M00 checks `CTL-01-keys`, `CTL-01-defaults`, `CTL-01-hold`, `US-009-1`, `US-009-1-freed`, `US-009-2`, `US-064-1`, `US-064-2` and `CLB-02-velocity` run in singleplayer with CBA; `US-009-2`, `US-064-1` and `US-064-2` with CBA and ACE; `US-009-1-freed` and `MP-01-drawn` on a dedicated server with two clients. On the same build of the mod they reach the verdicts its PowerShell suite reaches. Their late-joiner cases wait for `MCH-01` (deferred 04).
8. `NFR-PF-01`, `NFR-RL-01` and `NFR-RL-02` hold over the ported runs, and `SPK-14` has set `NFR-PF-06`.
9. Every story of milestones M0 to M9 has passed in the acceptance coverage, and `python3 tools/okf_check.py` lists no `must` story that no milestone delivers.
10. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
11. The owner has run the demo on the Windows test machine.

## Left out

Every `should` and `could` requirement (phase 2 and 3 of the implementation plan).
