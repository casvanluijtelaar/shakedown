# M13 Every setup, repeated

## Goal

Make the whole suite one command a test author walks away from, and make a flaky check visible. arma-grappling-hook runs its suite as three commands, one per setup, 189, 135 and 102 s each; its `US-064-1` failed 2 times in 13 with ACE, which only many runs by hand showed (M10 report); and the time each check takes was measured by hand.

## Demo

`shakedown run --each-setup --repeat 5` on arma-grappling-hook's suite runs every check in `sp-cba`, `sp-cba-ace` and `dedicated-cba`, one session after the other, reports `US-064-1` in `sp-cba-ace` with the counts of its outcomes, flags its slowest steps, and leaves three result files and nothing running.

## Stories

- `US-074` (feature) One command runs a selection in every setup it needs
- `US-075` (system fail) One setup's session fails to start in a run over every setup
- `US-076` (feature) Repeat a check and see how often each outcome came up
- `US-077` (system fail) The session breaks during repeats
- `US-078` (feature) Slow steps and slow checks are flagged
- `US-080` (mistake) A slow step threshold that is not a number of seconds

## What it builds

- `run --each-setup` and its MCP form (`RUN-07`), in the CLI and MCP contracts.
- `run --repeat` and the summaries of `DM-09` (`OUT-02`), in the CLI and MCP contracts and the result file's schema.
- The project key `slow_step` and the `slow` flag (`TIM-01`), in the CLI contract and the result file's schema.
- A fixture check that passes about one time in two, for the flaky summary.
- `docs/`: running every setup, repeats and flaky checks, slow steps.

## Spikes

None.

## Exit criteria

1. `US-074`, `US-075`, `US-076`, `US-077`, `US-078` and `US-080` pass their acceptance criteria on the test machine.
2. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
3. The owner has run the demo on the Windows test machine.

## Left out

- Running two setups' sessions at once: one game at a time on the test machine.
- A threshold per step or per check: one project-wide `slow_step` and half the timeout serve the port.
