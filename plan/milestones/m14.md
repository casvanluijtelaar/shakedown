# M14 Reload without a game restart

## Goal

Close the gap against G2 for mod code as far as the game allows (`DEF-21`). Every change of a mod's code is a game restart of 46 to 82 s (`NFR-PF-02`), while the PRD's loop is under 30 s. arma-grappling-hook's next milestones are mostly mod code (the thrown hook, climbing), so each edit of theirs pays a game start. The M10 port did not exercise a reload of that mod (exit criterion 3, waived with the demo).

Spike `SPK-19` passed (research `31-spike-reload-release.md`): every machine that reads 640 MiB of other loose files through file patching lets go of the files it held, and a mission restart then takes a changed `.sqf` on every machine, 10 of 10 on a dedicated session with two clients and 10 of 10 in singleplayer. In singleplayer that reload takes about 11 s against a game start of about 27 s. On a dedicated session it takes about 55 s, as long as a game restart, because the mission restart starts new clients (`P-08` step 4). It keeps the server's process.

## Demo

A changed function of arma-grappling-hook, a `CfgFunctions` function, is reloaded into a running `sp-cba` session at level `mission-restart`, and a check of the mod that calls it, rerun on it, passes with the new code, from the save to the verdict in under 30 s. The same change reloaded into a running `dedicated-cba` session reaches `server`, `p1` and `p2` at level `mission-restart`, with the server keeping its process, and `US-009-1-freed` rerun on it passes.

## Stories

- `US-081` (feature) A changed function reaches a running session without a game restart
- `US-082` (system fail) The game still holds the changed file

## What it builds

The way `SPK-19` passed, written first into `RLD-02`, `P-08`, `RLD-03`, `RLD-05`, `RLD-06`, `RLD-07`, the command line and agent tool contracts (the level `mission-restart` in the reload result) and `docs/reloading.md`:

- **The level.** A changed `.sqf` of a watched mod that the build already holds is level `mission-restart`, with the reason that the game is made to let go of the file and a mission restart compiles it again. New and deleted files, `config.cpp` and the other kinds of file stay `game-restart`. A reload applies the highest level any file needs, so one `config.cpp` among the files makes it a game restart.
- **The release files** (`RLD-07`). One 8 MiB file and 80 junctions to its folder (640 MiB through 80 paths), in the folder `skd_release` of the game folder, which no PBO covers, made by the runner when the first reload needs it and kept.
- **The reload at level `mission-restart`**, one step on the runner:
  1. Every machine of the session reads the 80 paths with `loadFile`, all machines at once, within a ceiling of 60 s.
  2. The runner checks that no game process holds a changed file by opening for writing the file the game reads for it, under the game folder at the mod's `prefix`. If one still does, step 1 runs once more.
  3. With every file free, it runs each setup mod's `rebuild` (`RLD-06`), as a game restart does. The game still holds the PBOs and every other file it read, so a rebuild at this level copies the changed loose files; a `hemtt build` that rewrites a held PBO fails.
  4. It restarts the mission as `P-08` steps 3 and 4 do. In singleplayer `p1` keeps its process. On a dedicated session the server keeps its process and the clients and headless clients start again.
  5. It verifies as `P-08` step 6 does. After this and every later mission restart until a game restart, every machine recompiles each `CfgFunctions` function whose file the reload changed, since the Functions Library compiles an addon's function once per game process and copies it into each new mission (research `27-spikes-reload.md`); arma-grappling-hook's functions are `CfgFunctions` functions. A check after such a recompile records `reload: partial` (`RLD-05`, `DM-08`).
- **A held file on demand** (`FIX-04`): `skdfx_fnc_holdFile` has the fixture's extension hold a file open for reading only in the game process, so a test brings about `US-082`.
- **The fallback** (`US-082`): when a file is still held after the second read, the reload applies `game-restart` instead. Its result names the file, the machine whose process holds it, found through the Windows Restart Manager, and that reason (`RLD-02`, `RLD-03`).
- `RLD-02`, `P-08`, `NFR-PF-01`, `NFR-PF-02`, `US-054`, `US-055`, `FIX-03` and the fixture contract edited to the level `mission-restart`. `NFR-PF-02` gets a target for the `mission-restart` reload from M14's own ten reloads: research 31 measured about 11 s in singleplayer and about 55 s on a dedicated session with two clients. `US-054` and `US-055` describe the reload of a `.sqf` at that level and keep the game restart for a new file and for config. `FIX-03`'s two reload targets may be changed during a reload's `rebuild` once the reload has freed them.

## Exit criteria

1. `US-081` and `US-082` pass their acceptance criteria on the test machine.
2. `DEF-21`'s acceptance criteria hold.
3. The spike's result is in `research/`, and the spec is edited in place to what it found.
4. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
5. The owner has run the demo on the Windows test machine.

## Left out

- G2's 30 s for mod code on a dedicated session (`DEF-32`): the mission restart starts new clients, so the reload costs a client start.
- `BIS_fnc_recompile` mid-mission (`SPK-09`) and any level inside the mission: a CBA `PREP` function is final, and a recompile in place is `DEF-32`'s option.
- `DEF-21`'s second and third options, ACE3's layout and text injection: the first option passed.
- Finding the exact size of other reads that frees a file: the fallback covers a machine where 640 MiB falls short.
