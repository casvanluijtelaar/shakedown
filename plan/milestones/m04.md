# M4 Agent tools

## Goal

Let the owner's AI agents drive Shakedown as tools: start sessions, run arma-grappling-hook's checks, follow long runs, run code, wait and ask a running game what is going on, with the same results a person gets from the command line. From here on every command lands with its tool.

## Demo

In Claude Code on the test machine, with the project's `.mcp.json`, an AI agent starts a singleplayer session with arma-grappling-hook, runs the M1 check through `run_start` and `run_status`, reads `run_result`, and asks `inspect` where `p1` stands, with no command typed by a person.

## Stories

- `US-001` (feature) Start a singleplayer session once and run many checks against it
- `US-003` (system fail) A start is refused before any process starts when Steam, the game or a mod is missing
- `US-005` (mistake) A second session start while one runs is refused
- `US-006` (mistake) A malformed project file or an unknown setup is refused with the key at fault
- `US-013` (feature) Run code on a chosen machine and get the result back as data
- `US-014` (mistake) Code for a machine the session does not have, or code that does not compile
- `US-023` (feature) Wait for an outcome on a machine with a ceiling, never a fixed sleep
- `US-031` (feature) Run one check, a list of checks, or the checks a story or finding names
- `US-032` (mistake) A selection that matches no check
- `US-042` (feature) Each machine's log is kept with the run and can be filtered
- `US-046` (feature) See the runner, the session and the active run at any time
- `US-047` (mistake) A command that needs a session when none runs
- `US-048` (feature) An AI agent uses every capability as tools, with the same results as the command line
- `US-049` (mistake) An AI agent's fixable mistake gets a code and the next step
- `US-050` (feature) An AI agent follows a long run without a tool call timing out
- `US-051` (system fail) A cancelled tool call stops the work it started in the game
- `US-061` (error) Code sent to a machine raises a script error
- `US-062` (error) A wait's condition raises a script error or returns no Boolean

## What it builds

- `shakedown mcp` with `rmcp` (`AGT-01`, `INT-MCP-01`) and `.mcp.json` (`INT-CC-01`), a tool for every command that exists, each with an `outputSchema` from the same types as the result file and the error codes of the MCP contract (`AGT-02`).
- The 60 s cap, `wait_s` and progress notifications (`AGT-03`), cancellation that stops the game-side work (`AGT-04`), `status` without a runner or a game, on Windows, macOS and Linux (`AGT-05`, `NFR-PT-02`), `guide` (`AGT-06`), and results over 20,000 characters written to a file (`AGT-07`).
- On the command line and as tools: `exec`, `wait`, `expect`, `inspect` of a machine that answers (`INS-01`) and `errors` (`ERR-05`), with `CTL-05` and the condition rule of `OBS-01`.
- `--json` on every command, the same JSON as the tool (`NFR-US-03`), and the refusals of `SES-02` and `SES-03` with their next step.
- `docs/`: the tools, the agent's workflow, and `guide`'s text.

## Exit criteria

1. `US-001`, `US-003`, `US-005`, `US-006`, `US-013`, `US-014`, `US-023`, `US-031`, `US-032`, `US-042`, `US-046`, `US-047`, `US-048`, `US-049`, `US-050`, `US-051`, `US-061` and `US-062` pass their acceptance criteria on the test machine, and `US-046`'s third criterion on the Mac.
2. The demo runs in a fresh Claude Code session.
3. 100 `exec` round trips per machine kind have a 95th percentile under 1 s (`NFR-PF-03`).
4. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
5. The owner has run the demo on the Windows test machine.

## Left out

A session that outlives the Claude Code session that started it, and the runner's own failures (M5). `inspect` of a machine that stopped answering (M9). `run_stop` (M8) and `reload` (M6) arrive with their stories.
