# M12 Shared helpers and mod events

## Goal

Remove the copies the M10 port had to make. Each of arma-grappling-hook's rope checks carries the same 200-line rope kit (`DEF-27`, finding `m10-4`), and the kit installs its own `agh_holderChanged` and `agh_refused` handlers, which stay for the mission because no check can remove them (that repository's `acceptance/docs/shakedown-suite.md`, "State a check leaves"). A library and recorded events take both out of the checks, before the M01 throw checks are ported and copy the kit again.

## Demo

arma-grappling-hook's rope checks run with the rope kit in `tests/_lib/` and its event lists from recorded `agh_holderChanged` events, in `sp-cba` and `dedicated-cba`, with the verdicts they reach today.

## Stories

- `US-070` (feature) Checks share helper code from a library folder
- `US-071` (mistake) A library file that does not compile
- `US-072` (feature) Record a mod's events on every machine and wait for one
- `US-073` (error) An awaited event never comes

## What it builds

- The library folder (`API-06`): the project key `lib`, the compile on every machine after the mission starts and after each reload, `list` and `run` skipping it, and its compile errors.
- Event recording and waits on events (`EVT-01`) in the check API contract and the addon, with the handlers removed at the check's end and the events in the result file.
- No new fixture behaviour: the fixture's keybind raises the CBA global event `skdfx_signalled` already (`spec/contract/fixture-mod.md`), which the event checks fire with `skd_fnc_pressKey`, and a check raises it on one machine alone with `CBA_fnc_localEvent`.
- `docs/`: shared helpers and events; `docs/porting-a-suite.md` says an old suite's shared library goes into the library folder.
- In arma-grappling-hook's repository, by its own roles: the rope kit moved into the library.

## Spikes

None.

## Exit criteria

1. `US-070`, `US-071`, `US-072` and `US-073` pass their acceptance criteria on the test machine.
2. `DEF-27`'s acceptance criteria hold.
3. Every check and test it adds carries the story or requirement ID it proves (`NFR-MT-02`), the gates of `NFR-MT-03` pass, and `docs/` say how to use what it built.
4. The owner has run the demo on the Windows test machine.

## Left out

- `skd_fnc_pressKey` returning the keybind's value (`DEF-26`): the documented way round works until a second mod needs it.
- Engine events on objects, such as `Hit` on a unit: the mission events and CBA events cover what the port records.
